L01 · Welcome to JavaScript

Q1
What is JavaScript's primary role in web development?
C) Adding interactivity and behavior
Why: HTML structures and CSS styles; JavaScript responds to clicks, updates content, validates forms. Storing data in databases is a back-end job.
Q2
JavaScript and Java are the same language.
B) False
Why: the name rode Java's 1990s popularity — a marketing decision. They are separate languages with different designs.
Q3
Which of these does a browser need to run JavaScript?
C) Nothing extra — browsers have a built-in JavaScript engine
Why: every modern browser ships an engine (V8, SpiderMonkey, JavaScriptCore). Node.js is for servers; no compiler or plugin is needed.
Q4
In the exercise, what happened when you typed document.title = "I changed this with JavaScript!" into the Console?
A) The text in the browser tab changed, just for your copy of the page
Why: document.title is the tab text, not the <h1>. The change lives only in your browser — a refresh puts it back.
Q5
What is ECMAScript?
D) The official specification (rulebook) that JavaScript follows
Why: engines implement the spec; names like ES6/ES2015 are editions of it. It isn't an engine, a server runtime, or a replacement language.
Exercise solution — Spot JavaScript in the Wild

Look for: the Console opened (not Elements); document.title returned the title as a quoted string; the tab text changed after assignment; the page turned light yellow; a refresh restored both. Their list of three features should be things that change without a full reload (menus, live search, carousels, counters), each with a reason HTML/CSS can't do it. Worksheet and expected results: labs/module-1/l01-welcome-to-javascript/README.md; the statements as a script: labs/module-1/l01-welcome-to-javascript/solution/.

L02 · Linking Scripts & the Console

Q1
Where is the recommended place to put a <script> tag that links to an external file?
B) Just before the closing </body> tag
Why: all the HTML has been parsed by then, so every element exists when the script runs. (In the <head> with defer is also correct — the option says "without defer.")
Q2
What does console.log() do?
A) Prints a message to the browser's Developer Tools Console
Why: it's a developer tool — visitors never see it unless they open DevTools. Putting text on the page is Module 4.
Q3
What does the defer attribute do on a <script> tag?
C) Downloads the script in parallel and runs it after HTML parsing completes
Why: the download doesn't block parsing, and deferred scripts run in order once the document is parsed. It only works on external scripts.
Q4
What happens with this code? <script src="app.js"> console.log("Hi!"); </script>
D) app.js runs, but the console.log() inside the tags is ignored
Why: when a script has src, its contents are ignored — silently, with no error. Use a separate <script> for inline code.
Q5
Which of these is a good JavaScript comment?
A) // Start at 3 lives so new players aren't punished too early
Why: it explains why, which the code can't. B only restates the code; C is HTML comment syntax; D is Python/shell syntax.
Exercise solution — Your First JS Project

Look for: a js-practice folder with index.html and app.js side by side; <script src="app.js"></script> just before </body>; in the Console a log, a yellow warning, a red "not a real one!" error, an info line, 5 + 3 = 8, 10 * 4 = 40, and a table of HTML/CSS/JavaScript. L03 · Variables & Data Types

Q1
Which keyword should you use by default when declaring a variable?
C) const
Why: it prevents accidental reassignment. Switch to let only when the value needs to change; var is legacy, and define isn't JavaScript.
Q2
What is the result of typeof null?
B) "object"
Why: a bug from 1995 that can't be fixed without breaking old sites. Check for null with value === null.
Q3
What does "5" + 3 evaluate to?
B) "53"
Why: with a string on either side, + concatenates: 3 becomes "3" and the strings join.
Q4
You write let favoriteColor; and then console.log(favoriteColor);. What appears in the console?
A) undefined
Why: the variable exists but has no value yet. null only appears if you assign it; a ReferenceError means the variable was never declared.
Q5
Which of these is a valid JavaScript variable name?
D) $totalScore
Why: it starts with $ and has only letters after. 2ndPlace starts with a digit, user-name has a hyphen, const is reserved.

L04 · Operators & Expressions

Q1
What does 10 % 3 return?
B) 1
Why: % is the remainder: 10 ÷ 3 = 3 remainder 1.
Q2
What does 5 === "5" return?
A) false
Why: strict equality checks value and type; a number and a string are different types. (5 == "5" would be true.)
Q3
What is the result of true && false || true?
B) true
Why: && goes first: true && false is false; then false || true is true.
Q4
After this code runs, what is the value of points? let points = 10; points += 5; points *= 2;
C) 30
Why: += 5 makes it 15, then *= 2 doubles the current value to 30.
Q5
Which of these values is truthy?
D) "0"
Why: it's a non-empty string (one character), so it's truthy — even though the number 0 is falsy. "" and NaN are falsy too.

L05 · Conditionals

Q1
What does this code output?
let x = 5;
if (x > 10) {
    console.log("A");
} else if (x > 3) {
    console.log("B");
} else if (x > 1) {
    console.log("C");
} else {
    console.log("D");
}
B) B
Why: 5 > 10 is false, but 5 > 3 is true, so "B" prints. The chain stops at the first true condition, so x > 1 is never checked.
Q2
What happens if you forget break in a switch case?
B) Execution falls through to the next case
Why: without break, the next case's code runs too, whether or not it matches. No error, no jump to default.
Q3
What does let result = 10 > 5 ? "yes" : "no"; assign to result?
A) "yes"
Why: the condition is true, so the ternary returns its first value. It returns one of its two values, never a boolean.
Q4
What does this code output?
let input = "5";
switch (input) {
    case 5:
        console.log("number five");
        break;
    default:
        console.log("no match");
}
C) no match
Why: switch compares with strict equality (===); the string "5" is not === the number 5, so default runs. Convert first with Number(input).
Q5
A shopping cart stores let quantity = 0; and zero is a perfectly valid quantity. Why is if (quantity) { ... } a risky way to check that a quantity was entered?
D) 0 is falsy, so a valid 0 would be treated as "missing"
Why: 0 is on the falsy list. When zero is legitimate, check explicitly, e.g. quantity !== undefined.
Exercise solution — Grade Calculator

Look for: an invalid-score check first (score < 0 || score > 100) wrapping the rest in else; an else if chain from >= 90 down storing letterGrade; a switch on letterGrade with a break in every case; const status = score >= 60 ? "Pass" : "Fail"; output "Alex scored 78 (C) — Solid effort, keep improving!" and "Status: Pass". Test with 95 (A), 60 (D, Pass), 59 (F, Fail), −5 and 105 (Invalid score). Reference: labs/module-2/l05-conditionals/solution/.

L06 · Loops

Q1
How many times does this loop run?
for (let i = 0; i < 3; i++) {
    console.log(i);
}
B) 3
Why: i takes 0, 1, 2; at 3 the condition i < 3 is false and the loop exits.
Q2
Which loop should you use to iterate over an array's values?
B) for...of
Why: for...of hands you each value directly. for...in gives string keys and belongs to objects.
Q3
What does continue do inside a loop?
B) Skips to the next iteration
Why: the rest of the current pass is skipped and the loop carries on. break is the one that exits.
Q4
What is the key difference between while and do...while?
D) do...while always runs its body at least once
Why: do...while checks its condition after each pass; while checks before, so it may run zero times.
Q5
What goes wrong with this loop?
const items = ["a", "b", "c"];
for (let i = 0; i <= items.length; i++) {
    console.log(items[i]);
}
B) It runs one extra time and logs undefined
Why: off-by-one. The last index is 2 but <= lets i reach 3, and items[3] is undefined (no error). Use < items.length.
Exercise solution — Star Rating & Search Filter

Look for: starRating looping i = 1; i <= 5 and appending i <= rating ? "★" : "☆", then returning the string (1 → ★☆☆☆☆, 3 → ★★★☆☆, 5 → ★★★★★); a for...of over products with product.toLowerCase().includes(searchTerm.toLowerCase()); a let matchCount declared outside the loop; output of the three Wireless products and "3 results found." Reference: labs/module-2/l06-loops/solution/.

L07 · Functions

Q1
What does a function return if it has no return statement?
B) undefined
Why: every call produces a value; with no return, that value is undefined. No error.
Q2
Which can be called before it's defined in the code?
A) Function declaration
Why: declarations are fully hoisted (name + body). const expressions and arrows are in the TDZ until their line runs.
Q3
What is the output of const fn = n => n * 3; console.log(fn(4));?
B) 12
Why: a one-expression arrow returns its expression implicitly: 4 × 3.
Q4
What does this code log?
function greet(name = "friend") {
    return `Hi, ${name}!`;
}
console.log(greet());
C) "Hi, friend!"
Why: no argument means name would be undefined, so the default "friend" kicks in.
Q5
Which arrow function correctly returns an object?
D) const make = n => ({ name: n });
Why: without the parentheses, the braces are read as a function body, so the function returns undefined. Wrapping in ( ) makes them an object literal.
Exercise solution — Mini Utility Library

Look for: capitalize as a declaration using str[0].toUpperCase() + str.slice(1).toLowerCase() (with an empty-string guard); clamp as a function expression (Math.max(min, Math.min(max, value))); pluralize as an arrow with plural = singular + "s"; temperatureConverter returning "32°F = 0.0°C", "100°C = 212.0°F", and "Invalid unit" for anything else. Every helper must return, not log. Reference: labs/module-2/l07-functions/solution/.

L08 · Scope & Hoisting

Q1
What is the output?
console.log(x);
var x = 10;
B) undefined
Why: the var declaration is hoisted and initialized to undefined; the assignment of 10 stays on its own line.
Q2
Which keyword creates a block-scoped variable?
B) let
Why: let and const stay inside their { }; var is function-scoped and leaks out of blocks.
Q3
What is a closure?
C) A function that remembers variables from its outer scope
Why: the inner function keeps access to its outer variables even after the outer function has finished — the basis of the private count in createCounter.
Q4
What happens when this code runs?
console.log(total);
let total = 50;
B) ReferenceError: Cannot access 'total' before initialization
Why: let is hoisted but not initialized; the line is inside the Temporal Dead Zone.
Q5
What does this code log?
const color = "blue";
function paint() {
    const color = "red";
}
paint();
console.log(color);
D) "blue"
Why: the inner color is a separate, function-scoped variable that shadows the global only inside paint(). No redeclaration error: they live in different scopes.
Exercise solution — Scope Detective & Score Tracker

Part 1 answers: 1 "block a" · 2 "global b" · 3 "function a" · 4 "function c" · 5 "function d" (var ignores the block) · 6 "global a" · 7 "global b" · 8 ReferenceError (c only exists inside test()). Part 2, look for: let score = 0 inside createScoreTracker; a returned object with addPoints, penalty using Math.max(0, score - points), getScore returning score, and reset. The usage sequence shows 30, then 0 after reset(); tracker.score is undefined. Reference: labs/module-2/l08-scope-closures/solution/.

L09 · Arrays

Q1
What is the index of the first element in a JavaScript array?
A) 0
Why: arrays are zero-indexed, so the first element is arr[0] and the last is arr[arr.length - 1].
Q2
Which method adds an element to the END of an array?
B) push()
Why: push adds to the end and returns the new length. unshift adds to the start; pop removes from the end.
Q3
What does splice() do?
C) Removes, inserts, or replaces elements at any position
Why: splice(start, deleteCount, ...items) edits the original array in place. Copying part of an array (A) is slice.
Q4
What does ["a","b","c"].includes("b") return?
B) true
Why: includes answers yes/no with a boolean. indexOf("b") would return the position, 1.

L10 · Objects

Q1
Which notation must you use when the key is stored in a variable?
B) Bracket notation
Why: bracket notation evaluates what's inside the brackets, so obj[field] uses the value stored in field. obj.field looks for a key literally named "field".
Q2
What does Object.keys({ a: 1, b: 2, c: 3 }) return?
B) ["a", "b", "c"]
Why: Object.keys returns the property names. Values (A) come from Object.values; pairs (C) from Object.entries.
Q3
Why shouldn't you use arrow functions as object methods that use this?
B) Arrow functions don't have their own this
Why: arrow functions inherit this from the surrounding scope, so inside an arrow "method" this isn't the object. Use the shorthand greet() { } syntax.
Q4
What does { x: 1 } === { x: 1 } evaluate to?
B) false
Why: objects are compared by reference. These are two separate objects in memory, so they're not equal even with identical contents.
Exercise solution — Contact Book

Look for: addContact checks for a duplicate name with find before push and returns true/false; findContact returns contact || null; updateContact reuses findContact and applies Object.assign(contact, updates) (or spreads the updates in); displayContact prints Name: Alice | Phone: 555-9999 | Email: alice@example.com | Group: friend after the update; listByGroup(contacts, "family") → ["Bob", "Dave"]. L11 · Array Methods

Q1
What does map() return?
B) A new array with the same number of elements
Why: map transforms each element and always returns a new array of the same length. Fewer items is filter; one value is reduce.
Q2
What does [1,2,3].filter(n => n > 1) return?
C) [2, 3]
Why: filter keeps elements whose callback returns true: 2 > 1 and 3 > 1 pass; 1 > 1 is false.
Q3
What is the second argument to reduce()?
B) The initial value of the accumulator
Why: reduce(callback, initialValue). The initial value is the accumulator's starting point. Always pass one, or an empty array throws a TypeError.
Q4
Which method modifies the original array?
C) sort()
Why: sort reorders the array in place. map, filter, and reduce return new values and leave the original alone. Use toSorted() or [...arr].sort() to keep the original.

L12 · Strings & Template Literals

Q1
Are JavaScript strings mutable or immutable?
B) Immutable — methods always return new strings
Why: every string method returns a new string; the original never changes. str[0] = "X" does nothing (or throws in strict mode).
Q2
What does "hello world".split(" ") return?
B) ["hello", "world"]
Why: split breaks the string at every space and returns an array of the pieces.
Q3
How do you check if a string ends with ".pdf"?
B) str.endsWith(".pdf")
Why: endsWith checks the end of the string, which is perfect for file extensions. includes would also match "my.pdf.txt".
Q4
What does "Hello, World!".slice(-6) return?
D) "World!"
Why: a negative start counts from the end: the last 6 characters are "World!".
Q5
What does "7".padStart(3, "0") return?
A) "007"
Why: padStart adds characters to the start until the string reaches length 3: "007". The result is still a string.

("Hello..." is 8 characters); slugify chains trim → toLowerCase → replace (strip specials, spaces → hyphens, collapse hyphens) for "my-blog-post-1"; countWords trims, returns 0 for an empty string, and splits on /\s+/ → 3 for " lots of spaces "; initials splits, maps each word to its first letter, joins, uppercases → "RDLP"; maskEmail splits on "@" and uses repeat → "r**@example.com". L13 · Introduction to the DOM

Q1
What is the DOM?
B) An in-memory tree of objects representing the page
Why: the browser builds the DOM from the HTML; JavaScript works on that tree, never on the file.
Q2
Which object is the entry point to the DOM?
B) document
Why: document represents the whole page and holds querySelector, createElement, etc. window is the browser window around it.
Q3
What does element.parentElement return?
B) The element that contains this element
Why: one step up the tree — an <li>'s parent is its <ul> or <ol>.
Q4
Your JavaScript adds a new <p> to the page. Where will you see it?
C) In the DevTools Elements panel
Why: the Elements panel shows the live DOM. View Source and the file in VS Code show the original HTML, which JavaScript never changes.
Q5
For a <ul> written on several indented lines, why might list.firstChild not be the first <li>?
D) The whitespace before the first <li> is a text node, and firstChild includes text nodes
Why: the line break and indentation become a text node. firstElementChild skips it.

Look for: each console task answered on the worksheet — the title, the h1, the section count, the breadcrumb, a sibling walk from document.body.firstElementChild, the changed heading and background, the link count; $0 used after selecting in the Elements panel; the bonus walk documentElement.children[1].children[3]… reaching the <h1>. L14 · Selecting & Modifying Elements

Q1
What does querySelector return if no element matches?
C) null
Why: no error at selection time — the error comes on the next line, when you read a property of null. (querySelectorAll is the one that returns an empty NodeList.)
Q2
Why should you avoid innerHTML with user input?
B) It can execute malicious scripts (XSS attacks)
Why: innerHTML parses HTML, so <img src=x onerror=…> runs the attacker's code. textContent treats it as plain text.
Q3
What method adds a CSS class without removing existing ones?
A) element.classList.add("new")
Why: className = and setAttribute("class", …) replace every class; toggle would remove it if it were already there.
Q4
Using the dataset property, how do you read data-item-id?
B) element.dataset.itemId
Why: dataset converts kebab-case to camelCase. dataset.item-id is a subtraction; getAttribute("data-item-id") works but doesn't use dataset.
Q5
Your stylesheet sets h1 { font-size: 2rem; }. What does heading.style.fontSize return if no inline style was set?
D) "" (an empty string)
Why: element.style reads only inline styles. getComputedStyle(heading).fontSize would give "32px".

L15 · Events & Event Listeners

Q1
What does addEventListener require as its two arguments?
B) An event type string and a callback function
Why: el.addEventListener("click", handler). An optional third argument holds options like { once: true }.
Q2
What is event.target?
B) The element that was actually clicked or interacted with
Why: the element the listener is attached to is event.currentTarget; with bubbling the two can differ.
Q3
What does event.preventDefault() do?
C) Cancels the browser's built-in behavior for that event
Why: e.g. a form reloading the page or a link navigating. Stopping the bubbling is stopPropagation(), a different method.
Q4
What is the main advantage of event delegation?
C) One listener handles events for all current and future children
Why: events bubble up to the parent, so elements added later are handled with no extra code.
Q5
How can you make a listener fire only once?
B) addEventListener("click", handler, { once: true })
Why: the options object is the third argument; the browser removes the listener after it fires.
Q6
A delegated listener on a list checks event.target.matches(".delete-btn"), but clicking the 🗑️ <span> inside the button does nothing. What's the fix?
A) Use event.target.closest(".delete-btn")
Why: the target is the <span>, which doesn't match. closest() checks the element itself and then walks up to the nearest matching ancestor.

L16 · Creating & Removing Elements

Q1
What does document.createElement("div") return?
B) A new <div> element in memory, not yet in the DOM
Why: it's invisible until you insert it with append, prepend, before or after.
Q2
What happens if you append an element that's already in the DOM?
B) It moves from its old position to the new one
Why: a DOM element can only be in one place at a time. Use cloneNode(true) for a copy.
Q3
What is the modern way to remove an element from the DOM?
C) element.remove()
Why: no parent reference needed. parentNode.removeChild() is the older pattern; display: none only hides it.
Q4
What does cloneNode(true) do compared to cloneNode(false)?
A) Deep clone (element + all children) vs. shallow clone (element only)
Why: true copies all descendants. Neither copies listeners added with addEventListener.
Q5
Why use a DocumentFragment when adding many elements?
C) It batches many insertions into one DOM update

L17 · Forms & Validation

Q1
How do you read what the user typed into a text input?
A) input.value
Why: .value is the current content of an input, textarea, or select, and it's always a string. textContent/innerHTML read the text inside ordinary elements, not what was typed.
Q2
What does event.preventDefault() do in a submit handler?
C) Stops the browser from reloading the page or navigating away
Why: by default a submit navigates to the action URL or reloads the page. preventDefault() keeps you on the page so JS can handle the data. Stopping bubbling is stopPropagation().
Q3
How do you check if a checkbox is checked?
D) checkbox.checked
Why: .checked is a live boolean. .value is the value attribute (often "on"), and getAttribute("checked") only shows the starting state.
Q4
When is the blur event useful for form validation?
B) When you want to validate after the user finishes with a field and moves on
Why: blur fires when the user leaves a field. They've finished typing, so it's a fair moment to judge. Every keystroke is input, and entering a field is focus.
Q5
Why is client-side validation not sufficient on its own?
C) Users can bypass it through DevTools, disabling JS, or direct API calls
Why: anything running in the browser is under the user's control. Client-side checks improve the experience, but only server-side checks protect the data.
Q6
You call email.setCustomValidity("Use your company email"). The user fixes the address, but the form still won't submit. Why?
D) The custom message was never cleared with setCustomValidity("")
Why: any non-empty custom message keeps validity.customError true. Your code must reset it with an empty string once the value is acceptable.

L18 · Timers & Animation

Q1
In the browser, what does setTimeout return?
D) A numeric timer ID you can pass to clearTimeout()
Why: the callback hasn't run yet when setTimeout returns. What you get back is the timer's ID, which is the handle you use to cancel it.
Q2
What will console.log("A"); setTimeout(() => console.log("B"), 0); console.log("C"); output?
B) A, C, B
Why: even with a 0 ms delay, the callback waits in the task queue until the running code (the call stack) finishes, so "C" logs before "B."
Q3
What's the difference between setInterval and recursive setTimeout?
C) setInterval fires every N ms regardless of how long the work takes; recursive setTimeout waits for completion first
Why: slow async work inside an interval can overlap. A recursive timeout schedules the next run only after the current one finishes, which guarantees a gap.
Q4
Why use requestAnimationFrame instead of setInterval for visual animations?
A) It syncs with the display's refresh rate for smooth frames and pauses in background tabs
Why: rAF runs right before each repaint (60/120/144 fps) and stops when the tab is hidden, which saves CPU and battery. setInterval has no idea when the screen redraws.
Q5
What is debouncing?
D) Delaying a function until events stop firing, resetting the timer on each new event
Why: each new event resets the timer, so the function runs once after a pause. Option A describes throttling.
Q6
In what order do setTimeout(…"timer"…, 0), Promise.resolve().then(…"promise"…), console.log("sync") log?
B) sync, promise, timer
Why: synchronous code runs first, then the browser empties the microtask queue (promise callbacks) before it takes the next task (the timer). The order they were scheduled in doesn't decide the order they run in.

L19 · Local Storage

Q1
What does localStorage.getItem("key") return if the key doesn't exist?
B) null
Why: a missing key gives null, not undefined or "", and it never throws. That's why loaders use stored ? JSON.parse(stored) : fallback.
Q2
What happens when you store a JavaScript object directly with setItem?
D) It's stored as the string "[object Object]"
Why: storage only holds strings, so the object is converted with .toString() and the data is lost. Use JSON.stringify first.
Q3
What is the correct way to store an array in Local Storage?
A) localStorage.setItem("data", JSON.stringify(myArray))
Why: JSON keeps the structure and types (nested objects, numbers, booleans). JSON.parse turns it back into an array. Passing the array directly gives a flat "1,2,3".
Q4
How does sessionStorage differ from localStorage?
C) sessionStorage data is cleared when the tab is closed; localStorage persists until deleted
Why: same API and a similar ~5 MB limit. The difference is lifetime and scope: session data belongs to one tab, while local data is shared across tabs of the same origin.
Q5
Why should you never store passwords or auth tokens in Local Storage?
C) Any JavaScript on the page can read it, making it vulnerable to XSS attacks
Why: an injected script can read every key. Auth tokens belong in HttpOnly cookies, which JavaScript can't read.
Q6
Your to-do app is open in two tabs. In Tab A you add a task (setItem("todos", …)). Where does the storage event fire?
B) In Tab B (and any other open tabs of the same origin), but not in Tab A
Why: the tab that made the change already knows about it. The event goes to the other tabs, which is what makes cross-tab sync possible.

L20 · Working with APIs & Fetch

Q1
What does fetch() return?
B) A Promise that resolves to a Response object
Why: the data isn't there yet. The Response comes first, and response.json() is a second Promise that gives you the data.
Q2
What happens when fetch() gets a 404 response?
A) The Promise resolves normally with response.ok set to false
Why: fetch only rejects for network failures. HTTP errors are still valid responses, so check response.ok or response.status yourself.
Q3
What does the async keyword do to a function?
C) Makes the function always return a Promise and enables the use of await inside it
Why: async doesn't create a thread or speed anything up. It wraps the return value in a Promise and allows await inside the function.
Q4
Why use Promise.all() instead of multiple sequential await calls?
B) It runs requests in parallel, so the total time equals the slowest request rather than the sum of all
Why: sequential awaits start each request only after the previous one finishes. Promise.all starts them all at once.
Q5
What are the three UI states every fetch operation should handle?
D) Loading, data (success), and error
Why: these are what the user sees. Pending/resolved/rejected are the Promise's internal states.
Q6
Your page on http://127.0.0.1:5500 fetches from another site's API, and the console shows a CORS error. What's going on?
C) The API server didn't send a header allowing your origin, so the browser won't let your code read the response
Why: permission comes from the server's Access-Control-Allow-Origin header. fetch rejects with a TypeError, and the fix belongs on the server (or a proxy of your own), not in your fetch options.

L22 · Next Steps & Best Practices

Q1
The console shows Cannot read properties of null (reading 'textContent'). What's the most likely cause?
C) querySelector didn't find the element, so it returned null
Why: querySelector returns null when nothing matches — usually a typo in the selector, or the script ran before the element existed. Reading .textContent on null throws this error.
Q2
A player's score is 0. What does const shown = player.score ?? 10; set shown to?
A) 0
Why: ?? only falls back when the left side is null or undefined. 0 is a real value, so it's kept. (With || you'd get 10, because 0 is falsy.)
Q3
You copy an object with const copy = { ...original }; and then push a new item onto copy.scores (an array). What happens to original.scores?
B) It changes too, because the nested array is shared
Why: Spread makes a SHALLOW copy: both objects share the same scores array. Use structuredClone(original) when you need a deep copy.
Q4
You want to start a new React project today. Which approach fits current best practice?
C) Use Vite (npm create vite@latest) or a framework like Next.js
Why: Vite (npm create vite@latest) or a framework like Next.js is the standard starting point now that Create React App is deprecated.
Q5
You add a debugger; line to your code and reload, but nothing pauses. What's the most likely reason?
B) DevTools wasn't open, so the browser ignored it
Why: The browser ignores debugger statements unless DevTools is open. Open DevTools (F12), then reload the page.
