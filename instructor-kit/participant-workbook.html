L01

Welcome to JavaScript

30 min
By the end you can
  • Explain what JavaScript adds to HTML and CSS
  • Tell front-end (browser) JavaScript from back-end (server) JavaScript
  • Describe how a browser runs JavaScript — and why it's called event-driven
  • Spot JavaScript at work on the sites you use
Key ideas
  • HTML = structure, CSS = presentation, JavaScript = behavior.
  • Every browser has a built-in JavaScript engine (Chrome/Edge: V8, Firefox: SpiderMonkey, Safari: JavaScriptCore). Nothing to install.
  • JS runs as the page loads, then waits for the user and reacts to clicks, typing, and scrolling.
  • JavaScript ≠ Java. ECMAScript is the official rulebook JavaScript follows (ES6 = ES2015).
Worked example — type these in the Console
document.title
// → the page's title, as a string

document.title = "I changed this with JavaScript!"
// → look at the browser tab

document.body.style.backgroundColor = "lightyellow"
// → the whole page changes color. Refresh: it all comes back.

L02

Linking Scripts & the Console

40 min
By the end you can
  • Link an external .js file with <script src="…">
  • Print to the Console with console.log() and friends
  • Explain where a script tag belongs and what defer does
  • Write comments that explain why
Key ideas
  • External files win (like a CSS stylesheet): clean HTML, reusable, cached, errors name a file and line.
  • If a <script> has a src, any code between its tags is ignored.
  • Put the script just before </body> (course default), or in the <head> with defer. A plain head script runs before the page exists.
  • console.log() prints to the Console, not the page. Also: .warn, .error, .info, .table, .group, .time.
  • Comments: // one line and /* many lines */.
Worked example — js-practice
<!-- index.html, inside <body> -->
<h1>JavaScript Practice</h1>
<p>Open the console to see messages.</p>
<script src="app.js"></script>

// app.js
console.log("app.js is connected and running!");
console.warn("This is a warning");
console.log("5 + 3 =", 5 + 3);
console.table(["HTML", "CSS", "JavaScript"]);

L03

Variables & Data Types

50 min
By the end you can
  • Declare variables with const and let (and know why to avoid var)
  • Name the everyday types: string, number, boolean, null, undefined
  • Check a type with typeof
  • Build strings with template literals: `Hi ${name}`
Key ideas — labeled boxes
  • const by default, let when the value will change, var only in old code. Reassigning a const throws a TypeError.
  • = means store ("gets"), not "equals."
  • Names: letters, digits, _, $; can't start with a digit; case-sensitive; no reserved words. Use camelCase.
  • null = deliberately empty; undefined = not assigned yet. typeof null is "object" — a famous bug.
  • "5" + 3 is "53" (joins), but "5" - 3 is 2. Convert on purpose with Number() / String().
Worked example
const firstName = "Ray";
let age = 30;
let nickname = null;

console.log(`firstName: ${firstName} (${typeof firstName})`); // firstName: Ray (string)
console.log(`Hello, ${firstName}! You are ${age} years old.`);

age = 31;             // ✅ let can change
// firstName = "Raymond";  ❌ TypeError: Assignment to constant variable

L04

Operators & Expressions

45 min
By the end you can
  • Do math with + - * / % ** and update values with +=, *= …
  • Compare with === and !== — and explain why not ==
  • Combine conditions with &&, ||, !
  • Predict an expression's result using precedence (or parentheses)
Key ideas
  • % is the remainder, not percent: 10 % 3 is 1.
  • === checks value and type: 5 === "5" is false. == converts types first and surprises you. Always use ===.
  • Falsy: false, 0, "", null, undefined, NaN. Everything else is truthy — even "0".
  • && runs before ||; * before +. Parentheses make it obvious.
  • Money: .toFixed(2) turns 34.199999999999996 into "34.20".
Worked example
const price = 29.99;
const quantity = 3;
const subtotal = price * quantity;
console.log(`Subtotal: $${subtotal.toFixed(2)}`);  // Subtotal: $89.97

let age = 25;
let hasID = true;
console.log(age >= 21 && hasID);   // true
console.log(5 === "5");           // false

L05

Conditionals

45 min
By the end you can
  • Write if, else if, and else to control program flow
  • Use switch to compare one value against many options
  • Pick between two values with the ternary operator (? :)
  • Use guard clauses and truthy/falsy checks for cleaner conditions
Key ideas
  • An else if chain is checked top to bottom; the first true condition wins and the rest are skipped. Check the highest range first.
  • switch compares with strict equality (===), so "5" never matches case 5. End each case with break, or it falls through.
  • Ternary: condition ? valueIfTrue : valueIfFalse. Keep it short; never nest them.
  • Guard clauses handle the problem cases first, so the main logic stays flat.
  • 0 and "" are falsy. If 0 is a valid value, don't test it with if (quantity).
Worked example
const score = 85;
let letter;

if (score >= 90) {
    letter = "A";
} else if (score >= 80) {
    letter = "B";
} else {
    letter = "C or below";
}

const result = score >= 60 ? "Pass" : "Fail";
console.log(`${score} → ${letter} (${result})`);   // "85 → B (Pass)"

L06

Loops

50 min
By the end you can
  • Write a for loop that repeats a set number of times
  • Use while and do...while when the count isn't known
  • Loop array values with for...of and object keys with for...in
  • Control a loop with break and continue; avoid infinite loops and off-by-one errors
Key ideas
  • DRY — Don't Repeat Yourself. Write the instructions once; the loop repeats them.
  • for when you know how many times; while when a condition decides; do...while runs at least once.
  • for...of → array values. for...in → object keys (not for arrays).
  • break exits the loop; continue skips to the next pass.
  • Index loops use i < array.length — <= runs one extra time and reads undefined.
Worked example
const numbers = [12, 35, 8, 67, 42];

for (const num of numbers) {
    if (num > 50) {
        console.log(`Found it: ${num}`);   // "Found it: 67"
        break;                           // stop searching
    }
}

L07

Functions

55 min
By the end you can
  • Write a function declaration and call it (even before its line — hoisting)
  • Write function expressions and arrow functions
  • Use parameters, arguments, and default values
  • Return a value and use it in an expression
Key ideas
  • A function is a recipe: define it once, call it with () whenever you need it. greet is the function; greet() runs it.
  • Parameters are the parking spots in the definition; arguments are the cars you pass in. A missing argument is undefined unless it has a default.
  • return hands a value back and exits immediately. No return → undefined.
  • Declarations are hoisted; const expressions and arrows can't be called before their line.
  • One-expression arrows return automatically: (a, b) => a + b. To return an object, wrap it: n => ({ name: n }).
Worked example
// Declaration — hoisted
function add(a, b) {
    return a + b;
}

// Expression — define before calling
const multiply = function(a, b) {
    return a * b;
};

// Arrow with a default parameter — implicit return
const greet = (name = "stranger") => `Hello, ${name}!`;

console.log(add(10, 20) * 2);   // 60
console.log(multiply(4, 5));    // 20
console.log(greet());            // "Hello, stranger!"

L08

Scope & Hoisting

45 min
By the end you can
  • Tell global, function, and block scope apart
  • Predict where a variable can and can't be used
  • Explain hoisting for var, let/const, and functions, including the Temporal Dead Zone
  • Explain what a closure is and build one
Key ideas
  • let/const are block-scoped (they stay inside { }). var is function-scoped and leaks out of if blocks and loops.
  • The scope chain: JavaScript looks in the current scope, then outward, up to global. It never looks inward.
  • Shadowing: an inner variable with the same name hides the outer one inside its scope only.
  • Hoisting: var starts as undefined; let/const throw a ReferenceError before their line (the TDZ); function declarations are fully hoisted.
  • A closure is a function that remembers the variables of the scope it was made in, even after that outer function has finished.
Worked example
function createCounter() {
    let count = 0;   // private — only the methods below can reach it

    return {
        increment() { count++; },
        getCount() { return count; }
    };
}

const counter = createCounter();
counter.increment();
counter.increment();
console.log(counter.getCount());   // 2
console.log(counter.count);        // undefined — count is not a property

L09

Arrays

50 min
By the end you can
  • Create an array and read or change any element by index (starting at 0)
  • Add and remove with push, pop, unshift, shift
  • Insert, remove, or replace anywhere with splice
  • Search with includes, indexOf, find; copy with slice and spread
  • Loop with for, for...of, and forEach
Key ideas
  • The first element is arr[0]; the last is arr[arr.length - 1] or arr.at(-1). Out of range gives undefined, not an error.
  • push/pop work on the end; unshift/shift on the start. push returns the new length; pop and shift return the removed item.
  • indexOf returns -1 when the value isn't there. Check for it before you splice.
  • splice changes the original; slice makes a copy. Same-sounding names, opposite effects.
  • A const array can still change its contents. const only stops you reassigning the variable.
Worked example
const colors = ["red", "yellow", "purple"];
colors.splice(1, 0, "orange");   // insert: ["red", "orange", "yellow", "purple"]
colors.push("blue");              // add to end
const i = colors.indexOf("yellow"); // 2
if (i !== -1) colors.splice(i, 1);  // remove it safely

for (const color of colors) {
  console.log(color);               // red, orange, purple, blue
}

L10

Objects

50 min
By the end you can
  • Create objects and read, add, update, and delete properties
  • Choose dot notation (default) or bracket notation (odd keys, keys in variables)
  • Write methods that use this
  • Work with nested data and arrays of objects; destructure properties
  • Loop over Object.keys, values, and entries
Key ideas
  • An object stores key: value pairs, so you look data up by name instead of position.
  • obj[field] uses the value of field; obj.field looks for a key literally named "field".
  • Inside a method, this is the object before the dot. Arrow functions don't have their own this, so write methods as greet() { … }.
  • An array of objects is like a spreadsheet: each object is a row, each key a column.
  • Objects are compared by reference: two objects with the same contents are still not ===.
Worked example
const player = {
  name: "Ray",
  score: 0,
  addPoints(points) {          // method: regular syntax, not an arrow
    this.score += points;
    return `${this.name}: ${this.score} points`;
  }
};
player.addPoints(10);          // "Ray: 10 points"

const { name, score } = player; // destructuring
for (const [key, value] of Object.entries({ name, score })) {
  console.log(`${key} → ${value}`);  // name → Ray, score → 10
}

Key ideas — one loop runs the whole app
  • Plan before you code. A feature list, the shape of one note object, and the loop above save hours of rework.
  • The data layer (loadNotes, saveNotes, createNote, updateNote, deleteNote, getNotes) knows nothing about the DOM. renderNotes() rebuilds the grid from the data every time.
  • One form, two modes: an empty hidden #note-id means "create"; an id means "edit."
  • Event delegation: the cards are rebuilt on every render, so one click listener on #notes-grid handles every ✏️ and 🗑️.
  • Graceful degradation: if the quote API fails, show a fallback and keep going. Everything the user typed goes in with textContent.
Worked example — one form, two modes
noteForm.addEventListener("submit", (event) => {
    event.preventDefault();
    if (!validateForm()) return;
    const editId = noteIdInput.value;          // "" or "1713300000000"
    if (editId) {
        updateNote(Number(editId), titleInput.value, bodyInput.value, categorySelect.value);
        showSaveStatus("Note updated!");
    } else {
        createNote(titleInput.value, bodyInput.value, categorySelect.value);
        showSaveStatus("Note saved!");
    }
    hideForm();
    renderNotes(searchInput.value, filterCategory.value);
});

Read it as the loop: the submit is the user action; createNote/updateNote update state and save; renderNotes re-renders. Number() is needed because input values are always strings.

Unexpected tokenSyntax error (missing bracket, comma)Check the line before the error line
Cannot read properties of undefinedA nested property's parent is missingLog the data's shape; use ?.
  • debugger; only pauses when DevTools is open. Or click a line number in Sources to set a breakpoint.
  • Pitfalls: queries can return null · fetch isn't finished on the next line · use === · spread copies are shallow (structuredClone is deep) · add delegated listeners once · test the edge cases (empty, zero, offline, first visit).
  • ?? falls back only for null/undefined; || also replaces 0, "" and false.
  • Organize by concern (data · rendering · events), name things for what they do, keep functions small. Split big projects into modules with <script type="module">; they need a server like Live Server.
