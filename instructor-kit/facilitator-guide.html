Module 1 — JavaScript Foundations

How to teach the four lessons that take students who already know HTML & CSS to their first real JavaScript: the Console, a linked script file, variables and data types, and operators. This is the start of the course — get every DevTools window open and every app.js linked before you move on.

4 lessons ~2.75 hrs teaching Lessons L01–L04 Level Beginner Maps to Day 1 AM

How to Use This Guide

  • Same rhythm as every module: Frame (why it matters) → Teach (live-code the concept) → Lab (students build) → Check (quiz + recap). Every lesson has a 5-question quiz and ends with 3–5 minutes for the lesson's Learning Journal prompt (in the lesson and the workbook). The minute timings in each teaching sequence add up to the lesson's length; adjust ±10 min to your group.
  • Live-code everything. Type into the Console and into app.js in front of the class — never paste finished code. Each lesson has a short live-demo script: type it exactly, in order, and say what you expect before you press Enter.
  • Blue blocks are concepts; teal blocks are hands-on; amber blocks are watch-outs. In Module 1 the watch-outs are mostly "where did my output go?" problems — the Console, the file link, and JavaScript's type surprises.
  • Quiz answers here are for you. The student workbook has a 3-question subset of each lesson quiz, without answers, labelled with the lesson's question numbers; the separate Answer Key covers every question with matching numbers for grading.
Before you start — Day 1 setup check (10 min, before L01)

Students come from the HTML & CSS course, so they should already have VS Code with the Live Server extension. Confirm it in the first ten minutes: everyone opens any folder in VS Code, right-clicks an .html file → Open with Live Server, and sees it at http://127.0.0.1:5500/…. Anyone missing Live Server installs it from the Extensions panel (search "Live Server" by Ritwick Dey).

Then have everyone open DevTools and the Console on that page, on their own OS — this is the most-used shortcut of the whole course:

Lesson Plans

L01

Welcome to JavaScript

30 min
Objectives
  • Explain what JavaScript is and what role it plays alongside HTML and CSS
  • Describe the difference between front-end and back-end JavaScript
  • Understand how the browser executes JavaScript
  • Identify real-world examples of JavaScript in action on web pages
  • Outline what they'll build throughout this course
Teaching sequence
  1. Frame (3m). "Your pages look great, but they don't do anything." Open a site the class uses and click a menu or type in a search box — that's JavaScript. Add the third layer to the house analogy they know: HTML is the skeleton, CSS the paint and furniture, JavaScript the electricity, plumbing, and elevator.
  2. The three layers (5m). Structure / presentation / behavior. Sell the head start: "You already know two-thirds of this."
  3. JavaScript in action (3m). Rapid-fire list from the room: dropdowns, live search, infinite scroll, form checks, a cart that remembers you. Land the aside: JavaScript ≠ Java — the name was a 1990s marketing decision.
  4. How browsers run it (4m). Every browser has a built-in engine (V8, SpiderMonkey, JavaScriptCore) — nothing to install. Walk the load story: parse HTML → load CSS and JS → display → wait for the user → react. That last loop is why front-end JS is called event-driven.
  5. History & ECMAScript (2m). Ten days in 1995; ES6 (2015) is where "modern JS" starts. ECMAScript = the rulebook; JavaScript = what browsers run.
  6. Front-end vs back-end + roadmap (3m). This course is front-end (the browser); Node.js is the server side, for later. Preview the six modules.
  7. Lab — Spot JavaScript in the Wild (6m). Console worksheet (below).
  8. Check + journal (4m). Quiz poll, then the journal prompt.
Live-demo script

On the practice page (labs/module-1/l01-welcome-to-javascript/starter/index.html), open the Console and type each line, predicting out loud first:

document.title
document.title = "I changed this with JavaScript!"
document.body.style.backgroundColor = "lightyellow"

Point at the browser tab after line 2, then refresh: everything comes back. "You changed your copy of the page, never the site's files." Repeat on a real site the class knows for the wow.

Lab — Spot JavaScript in the Wild

No files to write. Students follow the guided console worksheet in labs/module-1/l01-welcome-to-javascript/README.md: run the three statements on the practice page, refresh, then repeat on a site they use and list three features they think JavaScript drives. The solution page replays the statements from a script (with the output mirrored on screen) if you want to show the result on the projector.

Circulate for: the Console tab (not Elements) selected; the cursor in the Console's input line at the bottom; straight quotes, not curly ones.

Watch-outs
  • "Allow pasting" block. Chrome and Firefox refuse the first paste into the Console and ask you to type allow pasting. It's a real anti-scam feature, not an error. Tell students to type the lines — better practice anyway.
  • "I broke the website!" Some students fear the change is permanent. Refresh proves it isn't — and that answers quiz Q4.
  • Curly quotes copied from a document cause SyntaxError: Invalid or unexpected token. Retype the quotes.
  • Going too deep. Don't explain the DOM, document, or the engine internals yet. Today they only need "JavaScript can read and change the page."
Check for understanding — quiz (from the lesson) + journal

Answers: Q1 C) Adding interactivity and behavior; Q2 B) False; Q3 C) Nothing extra — browsers have a built-in JavaScript engine; Q4 A) The text in the browser tab changed, just for your copy of the page; Q5 D) The official specification (rulebook) that JavaScript follows. Full set in the Answer Key. Then give 3–5 minutes for the lesson's Learning Journal prompt: Pick a website you use every day and list three things on it that you now think are powered by JavaScript. For each one, explain why HTML and CSS alone couldn't do it. Name one feature you'd love to add to your own site — and one thing about how JavaScript works that still feels fuzzy. Students who prefer paper can use the workbook's Journal box; the online box saves only on that device.

L02

Linking Scripts & the Console

40 min
Objectives
  • Add JavaScript to an HTML page using the <script> tag
  • Tell inline scripts from external script files — and why external wins
  • Use console.log() and the other console methods
  • Open and use the DevTools Console for testing and debugging
  • Explain why script placement matters (head vs. body, defer)
Teaching sequence
  1. Frame (2m). "Last lesson you typed JavaScript into the Console. Now we make it part of the page, so it runs every time the page loads."
  2. Inline script (4m). Add a <script>console.log("Hello from JavaScript!")</script> before </body>. The message is in the Console, not on the page — say that twice.
  3. External file (6m). Move the code to app.js and link it with <script src="app.js"></script>. Compare it to linking CSS with <link>: separation of concerns, reuse, caching, errors that name a file and line. Then show the trap: code between the tags of a src script is ignored.
  4. Placement & defer (7m). Use the diagram below and the demo script: a script in the <head> runs before the body exists. Two fixes: before </body> (our course default) or defer in the head. Both are correct.
  5. The Console as a playground (4m). Shortcuts recap, then type 2 + 2, "Hello" + " " + "World", Math.random().
  6. Console methods (4m). log, info, warn (yellow), error (red), table, group, time. Pitch console.log() as their #1 debugging tool.
  7. Comments (3m). // and /* */. Comment the why, not the what — quiz Q5 tests exactly this.
  8. Lab — Your First JS Project (6m). Build js-practice.
  9. Check + journal (4m).
Diagram — when does app.js run?
Live-demo script — placement

Put this in app.js and move the <script> tag between the three positions. No DOM skills needed — document.body is either there or it isn't:

// app.js
console.log("Is the body ready?", document.body);

In the <head>: null. Before </body>: the <body> element. Back in the head with defer: the element again. That one line makes the whole placement rule concrete.

Lab — Your First JS Project

Students create a js-practice folder with index.html and app.js, link the script before </body>, and try every console method from the lesson. Starter in labs/module-1/l02-linking-scripts/starter/; solution in labs/module-1/l02-linking-scripts/solution/. This folder carries through L03 and L04 — tell them to keep it.

Circulate for: both files in the same folder; src="app.js" spelled exactly like the file; the page opened with Live Server; the Console open. Expected output: log, yellow warning, red "not a real one!" error, info, 5 + 3 = 8, 10 * 4 = 40, and a three-row table.

Watch-outs
  • Nothing in the Console. Check in order: file saved? src matches the file name, including case (App.js ≠ app.js on Linux servers)? Both files in the same folder? The Network tab shows a 404 for a wrong path — there is no other error.
  • Code inside a src script is silently ignored. Use a second <script> tag.
  • Script in the <head> without defer — fine for console-only code today, but the source of "can't find my element" bugs in Module 4. Build the before-</body> habit now.
  • The red line scares people. console.error("…not a real one!") is the demo. A real error starts with Uncaught and names a file and line — teach them to click that link.
  • The grey undefined after typing console.log("hi") in the Console is the return value of console.log, not a problem.
  • Filtered console. If warnings or info are missing, the log-level dropdown ("Default levels") or the filter box is hiding them.
Check for understanding — quiz (from the lesson) + journal

Answers: Q1 B) Just before the closing </body> tag; Q2 A) Prints a message to the browser's Developer Tools Console; Q3 C) Downloads the script in parallel and runs it after HTML parsing completes; Q4 D) app.js runs, but the console.log() inside the tags is ignored; Q5 A) // Start at 3 lives so new players aren't punished too early. Full set in the Answer Key. Journal prompt: Imagine a script in the <head> (without defer) tries to find your page's <h1>. Explain what goes wrong and two ways to fix it. Which will you use, and why? What's still unclear about when scripts run?

L03

Variables & Data Types

50 min
Objectives
  • Declare variables using let, const, and var — and explain the difference
  • Identify the primitive types: string, number, boolean, null, undefined, symbol, bigint
  • Use typeof to check a value's type
  • Follow naming rules and conventions (camelCase, UPPER_SNAKE_CASE, is/has booleans)
Teaching sequence
  1. Frame (2m). Programs remember things: a name, a score, a cart, "is logged in." Variables are how; types say what kind of thing.
  2. Variables as labeled boxes (5m). let username = "Ray"; — the label is the name, the value is inside. = is assignment ("store this"), not "equals." Reassign mood from "happy" to "excited".
  3. const / let / var (8m). Reassign a const live and read the TypeError aloud. Rule of thumb: const by default, let when it changes, never var in new code.
  4. Naming (4m). Hard rules (letters, digits, _, $; no leading digit; case-sensitive; no reserved words) vs conventions. Poll the class on 2ndPlace, user-name, $totalScore — that's quiz Q5.
  5. Data types (9m). String (three kinds of quotes, .length, template literals with ${…}), number (one type for integers and decimals; NaN, Infinity), boolean, null (deliberately empty) vs undefined (not assigned yet). Symbol and bigint: name them, skip them.
  6. typeof (4m). Run it on each type; save typeof null → "object" for last and tell the 1995 story. Check null with === null.
  7. Type conversion (6m). Explicit: Number("42"), String(19.99), Boolean(""). Implicit: "5" + 3 vs "5" - 3 — the biggest gotcha of the day.
  8. Lab — Build a User Profile (8m).
  9. Check + journal (4m).
Live-demo script
const SITE_NAME = "My Website";
let count = 0;
count = 1;                // fine — let can change
SITE_NAME = "Other";      // TypeError: Assignment to constant variable.

let futureValue;
console.log(futureValue);      // undefined
console.log(typeof null);    // "object" — the famous bug
console.log("5" + 3);         // "53"
console.log("5" - 3);         // 2

Pause before each console.log and take predictions from the room. Wrong predictions are the point.

Lab — Build a User Profile

In js-practice/app.js, students declare seven profile variables (firstName … nickname = null), log each with its typeof, build a template-literal greeting, update the let values, then try reassigning a const. Starter (L02 checkpoint + the lesson's TODO block) in labs/module-1/l03-variables-data-types/starter/; solution in labs/module-1/l03-variables-data-types/solution/.

Circulate for: const on firstName/lastName/email and let on the rest; backticks (not quotes) around template literals; the const reassignment left commented out afterwards, because an uncaught TypeError stops the rest of the file.

Watch-outs
  • Floating-point output. 149.99 - 29.99 prints 120.00000000000001. Not their bug: decimals are stored in binary. Format money with .toFixed(2) — the lesson solution does, and L04 relies on it.
  • "Identifier has already been declared." Students paste several lesson snippets into one app.js and declare price or name twice. That's a SyntaxError, and nothing in the file runs — not even the lines above it. (The Console lets you re-run let lines; a file doesn't. Say this out loud, or the difference will confuse them.)
  • const with objects and arrays. Someone will find that const colors = ["red"]; colors.push("blue"); works. const locks the variable, not the contents — you can't point it at a new array, but you can change what's inside. Acknowledge it, then park it for Module 3.
  • Quotes vs backticks. "Hello ${name}" prints the ${name} literally. Only backticks interpolate.
  • = read as "equals." Keep saying "gets" or "stores": age = 31 is "age gets 31." Comparison is next lesson.
Check for understanding — quiz (from the lesson) + journal

Answers: Q1 C) const; Q2 B) "object"; Q3 B) "53"; Q4 A) undefined; Q5 D) $totalScore. Full set in the Answer Key. Journal prompt: Think about your own website from the HTML & CSS course. List five pieces of information it could store in variables. For each, choose a data type and const or let, and explain why. Then describe null vs undefined in your own words. Which part still feels shaky?

L04

Operators & Expressions

45 min
Objectives
  • Use arithmetic operators, including % (remainder) and **
  • Apply assignment shorthand (+=, -=, *= …)
  • Compare values and explain the critical difference between == and ===
  • Combine conditions with &&, ||, !; know truthy and falsy
  • Predict how an expression evaluates using operator precedence
Teaching sequence
  1. Frame (2m). Variables store data; operators do something with it. An expression is any code that works out to a value — 2 + 3 is 5.
  2. Arithmetic (5m). The table from the lesson, then %: 10 % 3 is the remainder, 1. Even/odd with n % 2. count++ / count--.
  3. Assignment shorthand (3m). score += 25 means score = score + 25. Trace a short chain on the board (that's quiz Q4).
  4. Comparison — == vs === (8m). The heart of the lesson; see the demo script. Rule: always === and !==.
  5. Logical operators (5m). age >= 21 && hasID, isWeekend || isHoliday, !isLoggedIn. Short-circuiting in one sentence, and "" || "Guest" → "Guest" as a preview.
  6. Truthy & falsy (4m). The falsy list: false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy — including "0", [], and {}.
  7. String + & precedence (4m). + joins strings; prefer template literals. 2 + 3 * 4 is 14, not 20. "Use parentheses generously."
  8. Lab — Tip Calculator (10m).
  9. Check + journal (4m).
Live-demo script — the equality ladder
5 === 5          // true
5 === "5"        // false — different types
5 == "5"         // true  — == converts first
"" == 0          // true  (!)
"0" == 0         // true
"" == "0"        // false — so == isn't even consistent
null == undefined // true

Type these in the Console and let the class vote before each Enter. By line 6 the room will argue — then retype lines 4–6 with === and they all come out false. That settles the rule.

Lab — Tip Calculator

Students add a console tip calculator to js-practice/app.js: three const inputs, three calculations, four template-literal lines, and the bonus isExpensive comparison. Starter (L03 checkpoint + the lesson's TODO block) in labs/module-1/l04-operators-expressions/starter/; solution in labs/module-1/l04-operators-expressions/solution/.

Expected output: Bill: $85.50 · Tip (20%): $17.10 · Total: $102.60 · Per person: $34.20 · Expensive? true. Anyone showing 34.199999999999996 has forgotten .toFixed(2) — send them to the lesson's hint.

Watch-outs
  • Floating-point results. 102.6 / 3 is 34.199999999999996. It's normal; format for display with .toFixed(2). Note that .toFixed() returns a string — format at the end, don't do more math on it.
  • % is not "percent." Beginners write billAmount * 20%. % is remainder; a percentage is * tipPercentage / 100.
  • The $${…} pattern. In `Bill: $${billAmount.toFixed(2)}` the first $ is a literal dollar sign and ${ starts the placeholder. Students often drop one.
  • == "works" in their tests. 5 == 5 is true either way, so they think it doesn't matter. Show a mixed-type case every time.
  • const for results. The lesson declares tipAmount etc. with const because they're calculated once. If a student uses let, that runs fine — just ask "does this value ever change?"
Check for understanding — quiz (from the lesson) + journal

Answers: Q1 B) 1; Q2 A) false; Q3 B) true; Q4 C) 30; Q5 D) "0". Full set in the Answer Key. Journal prompt: Before running them, predict what "5" + 3, "5" - 3, 5 == "5", and 5 === "5" give, and why. Check in the console. Which surprised you? Explain why the course says always use ===. Think of a rule for your own site you could write with && or || — what's still confusing about combining conditions?

Lesson Plans

L05

Conditionals

45 min
Objectives
  • Write if, else if, and else statements to control program flow
  • Use switch for multi-branch decisions on one value
  • Write short value choices with the ternary operator (? :)
  • Replace deep nesting with guard clauses; use truthy/falsy values in conditions safely
Teaching sequence
  1. Frame (3m). "So far every line runs, every time. Real pages make choices: is the user logged in? Is the field empty? Is it morning?" Sketch a diamond on the board: condition → yes path / no path.
  2. if / else + logical operators (6m). Live-code the voting-age check, then combine with && (age and ticket) and || (weekend or holiday). Always type the braces, even for one line.
  3. else if chains — order matters (6m). Build the grade chain from >= 90 down. Then deliberately put >= 60 first and show every passing score becomes a D. "First true condition wins; the rest are skipped."
  4. switch (6m). The day-of-week example: stacked cases for Tuesday–Thursday, break, default. Delete one break to show fall-through, then put it back.
  5. Ternary (3m). const result = score >= 60 ? "Pass" : "Fail"; Read it aloud as "is it? then this : otherwise that." One level only — no nesting.
  6. Guard clauses + truthy/falsy (5m). Show the nested processOrder pyramid next to the flat guard-clause version. Then if (username) vs the long !== "" chain, and the 0 trap.
  7. Lab (10m). Grade Calculator (below).
  8. Check (3m). Quiz Q1–Q5 as a quick poll.
  9. Journal (3m). The lesson's prompt: one decision a page they'd like to build has to make, written as a plain-English if / else if / else chain.
Live-demo script
let score = 82;

if (score >= 90) {
    console.log("Grade: A");
} else if (score >= 80) {
    console.log("Grade: B");
} else {
    console.log("Keep going");
}
// Ask: "82 is also >= 70 — why don't we see C?"

Say: "JavaScript walks down the chain and stops at the first true condition." Change score to 95, 82, 40 and have the room call out the result before each save. Then type let input = "5"; and a switch with case 5: — let them predict, then show it falls to default. That's quiz Q4 taught in advance.

Lab — Grade Calculator

Students set studentName and score, pick the letter with an else if chain, pick the message with a switch, decide pass/fail with a ternary, and print "Alex scored 78 (C) — Solid effort, keep improving!" and "Status: Pass". Bonus: reject scores below 0 or above 100 first. Starter in labs/module-2/l05-conditionals/starter/; solution in labs/module-2/l05-conditionals/solution/.

Circulate for: the chain checking highest first; a break in every case; the letter stored in a variable before the switch. Make them test: 95, 60, 59, −5 and 105 — every branch plus both sides of the 60 boundary.

Watch-outs
  • switch uses strict equality (===). A string "5" never matches case 5:, and there's no error — it just drops to default. Anything read from a page is a string; convert with Number() first.
  • if (quantity) fails when 0 is valid. 0 is falsy, so a real zero looks "missing." Check explicitly (quantity !== undefined) when zero is a legitimate value.
  • = inside a condition. if (score = 90) assigns and is always truthy. When "every score is an A," look for a single equals sign.
  • Guard clauses before functions. The lesson's guard-clause example uses function and return, which aren't taught until L07. Tell students to read return; as "stop here and leave." In the lab, the guard is an if/else wrapper, not a return.
  • Missing break — the message for B shows the message for C too. Fall-through is only intentional for stacked cases.
Check for understanding

Run quiz Q1–Q5 as a quick poll. Key answers: Q1 x = 5 prints B (first true branch wins); Q2 missing break → falls through to the next case; Q3 10 > 5 ? "yes" : "no" → "yes"; Q4 switch("5") with case 5 → "no match" (strict equality); Q5 if (quantity) is risky because 0 is falsy, so a valid 0 looks "missing."

L06

Loops

50 min
Objectives
  • Write for loops that repeat a known number of times
  • Use while and do...while for condition-based repetition
  • Iterate arrays with for...of and object keys with for...in
  • Control loops with break / continue; avoid infinite loops and off-by-one errors
Teaching sequence
  1. Frame (3m). "Fifty products, fifty nearly identical lines? No." Introduce DRY — Don't Repeat Yourself. A loop writes the instructions once and repeats them.
  2. Anatomy of for (8m). Label the three parts on screen and say when each runs: 
    //   start;      keep going?;  after each pass
for (let i = 0; i < 5; i++) {
    console.log(`Iteration ${i}`);
}
    Then loop an array by index with i < fruits.length, count backward, and count by 2s.
  3. while / do...while (5m). The password-attempts while; then the dice-roll do...while. "do...while always runs its body at least once."
  4. for...of and for...in (6m). for (const color of colors) gives values. for (const key in user) gives keys. Show typeof key is "string" on an array to explain why for...in is for objects only.
  5. break & continue (5m). "Find the first number over 50" with break; "print only evens" with continue. break leaves the loop; continue skips to the next pass.
  6. Pitfalls (4m). Infinite loop (forgot count++) and off-by-one (<= length). Keep the infinite loop commented out — show, don't run.
  7. Lab (13m). Star Rating & Search Filter.
  8. Check (3m). Quiz Q1–Q5.
  9. Journal (3m). When would they pick for, while, for...of, for...in, and which loop fits a list from a page they'd like to build.

L07

Functions

55 min
Objectives
  • Write function declarations and explain that they are hoisted
  • Create function expressions and arrow functions (including implicit return)
  • Use parameters, arguments, and default values; return values and use them in expressions
  • Write small functions that do one thing, with clear names and early returns
Teaching sequence
  1. Frame (3m). The recipe analogy: define the recipe card once, cook it (call it) whenever you like, and swap ingredients (parameters) each time.
  2. Declarations + calling (6m). Write greet(). Show console.log(greet) (the function itself, nothing runs) vs greet() (the parentheses run it). Call sayHi() above its definition: it works, because declarations are hoisted.
  3. Parameters, arguments, defaults (7m). "Parameters are the parking spots; arguments are the cars." greet(name = "stranger"), then showInfo(1, 2) to show a missing argument becomes undefined.
  4. return (7m). add(3, 5) into a variable, then add(10, 20) * 2. return exits immediately (checkAge(-5)). A function with no return gives undefined.
  5. Function expressions (5m). const multiply = function(a, b) {…}; Try calling one above its line: ReferenceError. Compare with the declaration table.
  6. Arrow functions (7m). Shrink one function three times: 
    const add      = function(a, b) { return a + b; };
const addArrow = (a, b) => { return a + b; };
const addShort = (a, b) => a + b;   // implicit return
    Then the shortcuts: one parameter, no parameters, and => ({ … }) for objects.
  7. Best practices (3m). Do one thing; descriptive names; short functions; early returns (getDiscount before/after).
  8. Lab (11m). Mini Utility Library.
  9. Check (3m). Quiz Q1–Q5.
  10. Journal (3m). One job they repeated in L05–L06, described as a function: name, parameters, return value, declaration or arrow.
Live-demo script
const makeUser = n => { name: n };
console.log(makeUser("Ray"));   // Ask: "What prints?"

It prints undefined. Say: "JavaScript read those braces as a function body with a label called name, not as an object — and a body with no return gives undefined." Wrap it: n => ({ name: n }) and rerun. That's quiz Q5, and it's the single most confusing arrow rule.

Lab — Mini Utility Library

Four helpers: capitalize(str) as a declaration, clamp(value, min, max) as an expression, pluralize(count, singular, plural = singular + "s") as an arrow with a default parameter, and temperatureConverter(value, fromUnit) in any style, rounded with .toFixed(1) and returning "Invalid unit" otherwise. Files in labs/module-2/l07-functions/.

Circulate for: functions that console.log instead of return (the test line then shows undefined); expressions called above their definition; "0.0" — .toFixed(1) returns a string, which is exactly what the template needs.

Watch-outs
  • Logging instead of returning. A function that only logs gives undefined to its caller. console.log(greet()) prints the greeting and then undefined.
  • Hoisting: declarations vs const expressions. A declaration can be called above its line. A const/let function expression called early throws ReferenceError: Cannot access '…' before initialization — not a TypeError. (Only the old var form gives TypeError: … is not a function.)
  • Forgetting the parentheses. greet is the function; greet() runs it.
  • Braces on an arrow turn off implicit return. (a, b) => { a + b } returns undefined. Either drop the braces or add return.
  • Default parameters only fill undefined, not null or "". Mention it if someone asks; don't lead with it.
Check for understanding

Key answers: Q1 no return → undefined; Q2 callable before its definition → function declaration; Q3 fn = n => n * 3; fn(4) → 12; Q4 greet() with default "friend" → "Hi, friend!"; Q5 arrow returning an object → n => ({ name: n }).

Scope & Hoisting

45 min
Objectives
  • Explain global, function, and block scope; predict where a variable is accessible
  • Trace a lookup outward through the scope chain; recognize shadowing
  • Describe how var, let/const, and functions are hoisted; explain the Temporal Dead Zone

Teaching sequence
  1. Frame (3m). Scope answers one question: "Can I use this variable here?" Most "why is this undefined?" mysteries are scope.
  2. Global & function scope (4m). appName readable inside a function; taxRate inside calculateTotal is a ReferenceError outside. Two functions, two independent greeting variables. "Privacy is a feature."
  3. Block scope and the var leak (6m). let stays in its { }; var leaked escapes the if. Show for (var j…) leaving j = 3 behind. Mention the classic setTimeout 3, 3, 3 bug as a story, not a deep dive.
  4. Scope chain & shadowing (6m). Draw the nested boxes (diagram below): inner looks outward, never inward. Then color "red" inside paint() vs "blue" outside.
  5. Hoisting & the TDZ (7m). var nickname logs undefined before its line; let age throws a ReferenceError; declarations are fully hoisted; const function expressions are in the TDZ.
  6. Closures (5m). createGreeter("Hello"), then createCounter(): count survives after the outer function finishes, and nobody can reach it except the returned methods.
  7. Lab (8m). Scope Detective & Score Tracker.
  8. Check (3m). Quiz Q1–Q5.
  9. Journal (3m). Explain the var leak and the TDZ without looking back; explain the counter closure to a friend.
Live-demo script
console.log(nickname);  // ?
var nickname = "Ray";

console.log(age);       // ?
let age = 25;

Take predictions for each line, then run. undefined, then ReferenceError: Cannot access 'age' before initialization. Say: "Both were hoisted. var got a placeholder undefined; let is in the Temporal Dead Zone until its line runs — and that error is a favor, because a silent undefined is harder to debug." Lab — Scope Detective & Score Tracker

Watch-outs
  • Don't demo with var name. In a browser script, a global var name collides with the built-in window.name, which turns every value into a string and confuses the hoisting demo. That's why the lesson uses nickname. Stick to it when you improvise.
  • TDZ error is a ReferenceError, not a TypeError. Calling a const function expression before its line: "Cannot access 'greet' before initialization." Only var greet = function… produces "greet is not a function."
  • "var d is inside the if, so line 5 must fail." The most common wrong prediction: var ignores blocks and belongs to the whole function.
  • Thinking shadowing changes the outer variable. The inner const color = "red" is a different variable; the global stays "blue".
  • Closures sound abstract. Keep it concrete: "the function packs a backpack with the variables it could see when it was made." Mastery isn't the goal today; recognizing the pattern is.
Check for understanding

Key answers: Q1 console.log(x); var x = 10; → undefined; Q2 block-scoped keyword → let; Q3 a closure is a function that remembers variables from its outer scope; Q4 console.log(total); let total = 50; → ReferenceError: Cannot access 'total' before initialization; Q5 shadowed color → "blue".

Lesson Plans

L09

Arrays

50 min
Objectives
  • Create arrays with literal syntax (and know why to avoid new Array(3))
  • Read and update elements by index; use length and at(-1)
  • Add and remove with push/pop/unshift/shift; insert, remove, or replace with splice
  • Search with includes, indexOf, find; copy and combine with slice, concat, and spread
  • Loop with for, for...of, and forEach
Teaching sequence
  1. Frame (4m). Write const song1 = …; const song2 = …; const song3 = …; and ask "what about a playlist of 500?" An array is one variable holding an ordered list. Draw numbered slots on the board, starting at 0.
  2. Create, read, update (8m). Literal syntax, index access, animals[99] → undefined (no error!), last element via length - 1 and at(-1), and a quick array destructure const [r, g, b] = rgb. Show that const arrays can still be pushed: const locks the variable, not the contents.
  3. The four end methods (6m). push/pop at the end, unshift/shift at the start. Draw the array as a line of people: push = join the back, shift = serve the front. Point out that push returns the new length and pop/shift return the removed element.
  4. splice vs slice (10m). The lesson's hardest ten minutes. Run both on the same array and log the original after each: 
    const letters = ["a", "b", "c", "d", "e"];
letters.slice(1, 3);   // ["b", "c"] — letters unchanged
letters.splice(1, 2);  // ["b", "c"] — letters is now ["a", "d", "e"]
    Same return value, completely different side effect. Mnemonic: splice has a "p" for "permanent". Then show insert splice(1, 0, "x") and replace splice(1, 1, "x").
  5. Searching (6m). includes → true/false, indexOf → position or -1, find/findIndex with a condition. First look at a callback here: numbers.find(num => num > 10). Read it aloud: "find the first num where num is greater than 10."
  6. Combine & copy (5m). concat, then spread [...front, ...back] as the modern way; [...original] as a copy. Show the lesson's mutating vs non-mutating list.
  7. Iterating (5m). Same array three ways: for (need the index), for...of (default), forEach (callback with element + index; no break). End on the tax loop printing 32.400000000000006. Name it and park it: "floating point. We'll format money with toFixed(2)."
  8. Lab launch (2m). Hand off to the To-Do List Manager.
  9. Check & journal (4m). Quiz poll, then the journal prompt (splice vs slice in their own words).
Live-demo script
  1. Open the Console and type const todos = ["Buy groceries", "Walk the dog"]. Ask: "How do I get the dog walk?" Take answers. Someone will say todos[2]. Run it: undefined. That's the zero-index lesson, learned the memorable way.
  2. todos.push("Read"). Point out the Console echoes 3, the new length, not the array.
  3. todos.indexOf("Walk the dog") → 1, then todos.splice(1, 1). This is exactly the removeTodo recipe from the lab. Say so.
  4. todos.indexOf("Nap") → -1. "Not found is -1, and that's why we check for it before splicing." Then show why: todos.splice(-1, 1) quietly removes the last item.
Lab — To-Do List Manager

Students write addTodo, removeTodo, insertTodoAt, listTodos, and completeTodo on a shared todos array, then uncomment the tests. Starter in labs/module-3/l09-arrays/starter/; solution in labs/module-3/l09-arrays/solution/. Tell students to use show() where the lesson says console.log(): it logs and prints on the page.

Circulate for: the -1 check before splice in removeTodo; splice(index, 0, task) (zero delete count) for inserting; i + 1 in the numbered list; shift (not pop) in completeTodo. Early finishers: add a moveTodo(list, from, to) using two splices.

Watch-outs
  • splice vs slice. The #1 confusion of the lesson (quiz Q3 targets it). If a student's array "mysteriously lost items," look for a splice where they meant slice.
  • Off-by-one. The last index is length - 1; arr[arr.length] is always undefined. In loops, i <= arr.length runs one step too far.
  • if (list.indexOf(x)). Wrong in both directions: "found at index 0" is falsy and "not found" (-1) is truthy. Compare to -1 explicitly, or use includes for yes/no questions.
  • "But it's const!" Students expect const arrays to be frozen. push works; only todos = […] fails.
  • Expecting push to return the array. const list = todos.push("x") gives a number. That's why the lab functions push and then return list on its own line.
Check for understanding

Run quiz Q1–Q4 as a quick poll. Key answers: first index = A) 0; add to the end = B) push(); splice() = C) removes, inserts, or replaces at any position; ["a","b","c"].includes("b") = B) true (a boolean, not the index).

Journal (3–5 min)

Prompt: a list they'd like to build, which array methods they'd use on it, and splice vs slice in their own words. Read a few splice/slice answers aloud. They're a fast diagnostic for who needs a two-minute recap tomorrow morning.

Objects

50 min
Objectives
  • Create objects with literal syntax (including shorthand properties)
  • Read and write properties with dot and bracket notation; add, update, delete
  • Write methods and use this, and explain why arrow functions don't work as methods that need it
  • Nest objects and arrays; work with arrays of objects
  • Destructure objects; iterate with Object.keys/values/entries
  • Check for properties (in, Object.hasOwn, ?.) and explain reference equality
Teaching sequence
  1. Frame (4m). Recap day 2: "Arrays store by position. What's at user[2]? No idea." Objects store by name: user.email says what it is.

    const field = "name";
product[field];   // "Headphones" — uses the VALUE of field
product.field;    // undefined — looks for a key literally called "field"

  7. Iterating & spread (5m). Object.keys, values, entries with for (const [key, value] of …). Merge settings with { ...defaults, ...userPrefs }: later wins. Mention "shallow copy" once.
  8. Checking & comparing (4m). "email" in user vs !== undefined; optional chaining user.work?.zip. Then the predict-first moment: { x: 1 } === { x: 1 }. Draw the reference diagram below.

  10. Check & journal (3m).

  2. c.x = 99; then log a.x. Gasps are normal. "c isn't a copy, it's a second name for the same object." Then const d = { ...a }; d.x = 5; and a.x is still 99. That's a real copy.

Lab — Contact Book

L11

Array Methods

55 min
Objectives
  • Transform with map, keep matches with filter, collapse with reduce
  • Answer questions with find, some, and every
  • Sort numbers and objects with a compare function; know that sort mutates
  • Chain methods into a filter → sort → map pipeline and pick the right method for a task
Teaching sequence
  1. Frame (4m). Put the L09 tax loop on screen (empty array, for...of, push), then replace it with one line: prices.map(price => price * 1.08). "You describe what to do to each item; the method does the looping."
  2. forEach returns undefined (3m). const shouted = names.forEach(…) → undefined. forEach is for side effects (logging, later the DOM), not for building arrays.
  3. map (7m). Same length out as in. Strings from objects (users.map(u => u.name)), then the wrapped-object return u => ({ ...u, birthYear: … }). Point at the parentheses: without them, the braces are a function body.
  4. filter (6m). Callback returns true = keep. Passing scores, in-stock products, and "remove all Walk dog" as the non-mutating alternative to splice.
  5. reduce (10m). Slow down. Run the lesson's logging version so the Console prints every step: 
    numbers.reduce((sum, num) => {
  console.log(`sum: ${sum}, num: ${num}`);
  return sum + num;
}, 0);   // ← the initial value (quiz Q3)
    Act it out: the accumulator is a running total on a sticky note that gets handed from item to item. Then show the tally pattern ({} as the initial value) so they see reduce can build any value, not just a sum.
  6. find, some, every (5m). Questions, not transformations. some = "any?", every = "all?". Both stop early.
  7. sort (7m). Predict first: [40, 100, 1, 5, 25].sort(). Run it: [1, 100, 25, 40, 5]. The default sort compares as strings. Fix with (a, b) => a - b; flip for descending; localeCompare for names. Then show it mutated the original, and offer toSorted() / [...arr].sort().
  8. Chaining (6m). Build the electronics pipeline one method at a time, logging after each step. Read it top-down as a sentence. Filter first, because after map to names the price is gone.
  9. Lab launch (2m). "No loops allowed" is the rule.
  10. Check & journal (5m).
Live-demo script
  1. Paste the lab's 8-product array into the Console (it's in the starter). Ask for "just the names." Type products.map(p => p.name).
  2. "Only in-stock." Add .filter(p => p.inStock) before the map and run again. Count: 6.
  3. "Total value of in-stock." products.filter(p => p.inStock).reduce((sum, p) => sum + p.price, 0) → 374.94000000000005. Ask "is our math wrong?" No: decimals like 29.99 can't be stored exactly in binary. Add .toFixed(2) → "374.94", and point out the quotes: toFixed returns a string, meant for display. Do math on the raw numbers and format at the end.
  4. Deliberately break it: .map(p => { p.name }) → an array of undefined. Curly braces need return.
Lab — Product Catalog Pipeline

Six challenges on an 8-product array, each solved with array methods only. Files in labs/module-3/l11-array-methods/. Each challenge has its show() line pre-written and commented out. Students write the const, then uncomment.

Expected output to check at a glance: 8 names · 6 in stock · [Mousepad XL, Wireless Mouse, Mechanical Keyboard] · total "374.94" · every → true · a 6-line sale list from "Mousepad XL — $11.99 (was $14.99)" to "Headphones — $119.99 (was $149.99)". Challenge 6 is the stretch (filter → map → sort → map). Let strugglers stop at 5 and walk through 6 together at the end.

Watch-outs
  • Default sort() on numbers sorts alphabetically: [1, 100, 25, 40, 5]. Numbers always need (a, b) => a - b.
  • sort mutates. Quiz Q4. In the lab it's safe because filter already made a new array. Sorting products directly reorders the catalog for every later challenge. The solution page ends by proving the original order survived.
  • Floating-point output. 374.94000000000005 and 32.400000000000006 aren't bugs. Format with toFixed(2) for display, and remember it returns a string ("374.94" + 1 is "374.941").
  • Braces without return in a callback, giving [undefined, undefined, …]. And returning an object literal needs ({ … }).
  • reduce without an initial value. It works for sums on non-empty arrays, then crashes on [], and misbehaves on arrays of objects (the first accumulator is a whole product). Always pass the second argument.
Check for understanding

Key answers: map() returns B) a new array with the same number of elements; [1,2,3].filter(n => n > 1) = C) [2, 3]; reduce's second argument = B) the initial value of the accumulator; modifies the original = C) sort().

Journal (3–5 min)

Prompt: a plain-English filter → sort → map pipeline on their own data, why filter comes first, and what's still unclear (the lesson itself guesses reduce). Normalize it: "Most developers needed a few tries before reduce clicked."

L12

Strings & Template Literals

40 min
Objectives
  • Explain that strings are immutable: every method returns a new string
  • Use template literals for interpolation and multiline text
  • Search (includes, startsWith, endsWith, indexOf) and extract (slice, at)
  • Transform (toUpperCase, trim, replace/replaceAll) and split/join
  • Format with padStart, padEnd, and repeat
Teaching sequence
  1. Frame: immutability (3m). const g = "hello"; g.toUpperCase(); g is still lowercase. "String methods hand you a new string. Catch it in a variable." Contrast with push/splice, which changed arrays.
  2. Template literals (4m). Quick review of ${} with an expression and a ternary, then multiline. Note the lesson's warning: user text in an HTML template must be escaped before it goes near innerHTML (the next module comes back to this).
  3. Searching (4m). includes is case-sensitive, so use toLowerCase() first. endsWith(".pdf") for file types.
  4. Extracting (5m). String slice works exactly like array slice, including negatives. "Hello, World!".slice(-6): predict, then run. Mention substring exists and prefer slice. at(-1) for the last character.
  5. Transforming (6m). Case, trim ("always trim user input"), replace (first only) vs replaceAll. Show phone.replace(/\D/g, "") as a preview only. See the regex primer below.

Regex primer: say this before the lab

The lesson only previews regular expressions, but the lab's slugify, countWords, and initials use them. Without a minute of explanation, students copy them blindly or freeze. Put these on the board and read each one aloud:

/-+/g           // one or more hyphens, everywhere
/[^a-z0-9\s-]/g // any ONE character NOT (^) in the set [a-z, 0-9, space, hyphen]
/\D/g           // any non-digit (from the lesson's phone example)

Frame: "A regex is a pattern between slashes. You'll read these today, not write your own. split(/\s+/) splits on any run of spaces, which is why " lots of spaces " gives 3 words instead of empty strings."   • Calling a method and throwing the result away. name.trim(); on its own line does nothing. Strings are immutable (quiz Q1).
