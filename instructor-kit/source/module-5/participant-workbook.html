L17

Forms & Validation

55 min
By the end you can
  • Read what users type with .value (and .checked for checkboxes)
  • Stop the page reload with event.preventDefault()
  • Check required, length, format (regex), and matching fields
  • Validate on blur, then give live feedback on input
  • Explain why the server must check the data again
Key ideas
  • .value is always a string, even for number inputs. Convert with Number().
  • Listen for submit on the form, and call preventDefault() on the first line.
  • Touched fields: validate when the user leaves a field (blur), then re-check on every keystroke (input), but only after that first blur.
  • Show errors as text plus color, with role="alert" so screen readers announce them.
  • Client-side validation is for user experience. Anyone can bypass it, so the server always validates again.
Worked example
form.addEventListener("submit", (event) => {
  event.preventDefault();                 // no reload
  const email = form.elements.email.value.trim();
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    showError(form.elements.email, "Please enter a valid email");
    form.elements.email.focus();
    return;
  }
  console.log("Valid. Send it to the server, which checks again.");
});

L18

Timers & Animation

50 min
By the end you can
  • Run code later with setTimeout and cancel it with clearTimeout
  • Repeat code with setInterval and stop it with clearInterval
  • Tell debounce (wait for a pause) from throttle (at most once per window)
  • Explain why setTimeout(fn, 0) doesn't run "right now"
  • Animate with requestAnimationFrame or by toggling a CSS class
Key ideas — the event loop
  • Pass the function, don't call it: setTimeout(show, 1000), not setTimeout(show(), 1000).
  • Save the ID a timer returns. You need it to cancel the timer.
  • JavaScript does one thing at a time. Sync code runs first, then all promise callbacks (microtasks), then one timer or click (task).
  • A timer's delay is a minimum. For accurate countdowns, calculate from Date.now() instead of counting ticks.
  • For simple motion, CSS does the animating. JS just adds or removes a class.
Worked example
let intervalId = null;              // outside, so pause() can reach it

function start() {
  if (intervalId !== null) return;     // no double intervals
  intervalId = setInterval(() => {
    remainingSeconds--;
    updateDisplay(remainingSeconds);
    if (remainingSeconds <= 0) pause();
  }, 1000);
}
function pause() { clearInterval(intervalId); intervalId = null; }

L19

Local Storage

45 min
By the end you can
  • Save, read, and delete data with setItem, getItem, removeItem, clear
  • Store arrays and objects with JSON.stringify and read them back with JSON.parse
  • Choose localStorage or sessionStorage
  • Keep an app's state saved: load → render → change → save → render
  • Name what must never go in storage
Key ideas — everything is a string
  • Storage holds strings only. Saving an object directly stores "[object Object]".
  • getItem on a missing key returns null, so give it a fallback: stored ? JSON.parse(stored) : [].
  • Wrap JSON.parse in try/catch, because corrupted data throws.
  • localStorage lasts until it's deleted and is shared by tabs. sessionStorage is per tab and ends when the tab closes.
  • Any script on the page can read storage. Never store passwords or tokens there.
Worked example
function loadTodos() {
  try {
    const stored = localStorage.getItem("todos");
    return stored ? JSON.parse(stored) : [];
  } catch (error) {
    return [];                     // corrupted? start fresh
  }
}
function saveTodos(todos) {
  localStorage.setItem("todos", JSON.stringify(todos));
}

L20

Working with APIs & Fetch

60 min
By the end you can
  • Explain what an API, an endpoint, and JSON are
  • Describe a Promise's three states: pending, fulfilled, rejected
  • Fetch data with fetch() + await, and check response.ok
  • Handle errors with try/catch and friendly messages
  • Show loading, data, and error states safely
Key ideas — the fetch lifecycle
  • fetch() gives you a Promise right away, and the Response arrives later. await waits for it.
  • A 404 or 500 does not land in catch. fetch only rejects when the network fails. Check response.ok / response.status yourself.
  • response.json() is also a Promise, so it needs await too.
  • Every request has three UI states: loading, data, error.
  • API text (names, bios) was typed by other people. Put it on the page with textContent.
Worked example
async function fetchUser(id) {
  try {
    const response = await fetch(
      `https://jsonplaceholder.typicode.com/users/${id}`
    );
    if (!response.ok) {
      throw new Error(`Server error: ${response.status}`);
    }
    return await response.json();
  } catch (error) {
    console.error("Failed to fetch user:", error.message);
    return null;
  }
}
