L17 · Forms & Validation

Q1
How do you read what the user typed into a text input?
A) input.value
Why: .value is the current content of an input, textarea, or select, and it's always a string. textContent/innerHTML read the text inside ordinary elements, not what was typed.
Q2
What does event.preventDefault() do in a submit handler?
C) Stops the browser from reloading the page or navigating away
Why: by default a submit navigates to the action URL or reloads the page. preventDefault() keeps you on the page so JS can handle the data. Stopping bubbling is stopPropagation().
Q3
How do you check if a checkbox is checked?
D) checkbox.checked
Why: .checked is a live boolean. .value is the value attribute (often "on"), and getAttribute("checked") only shows the starting state.
Q4
When is the blur event useful for form validation?
B) When you want to validate after the user finishes with a field and moves on
Why: blur fires when the user leaves a field. They've finished typing, so it's a fair moment to judge. Every keystroke is input, and entering a field is focus.
Q5
Why is client-side validation not sufficient on its own?
C) Users can bypass it through DevTools, disabling JS, or direct API calls
Why: anything running in the browser is under the user's control. Client-side checks improve the experience, but only server-side checks protect the data.
Q6
You call email.setCustomValidity("Use your company email"). The user fixes the address, but the form still won't submit. Why?
D) The custom message was never cleared with setCustomValidity("")
Why: any non-empty custom message keeps validity.customError true. Your code must reset it with an empty string once the value is acceptable.
Exercise solution — Registration Form with Real-Time Validation

Look for: novalidate on the form; showError reusing an existing .error-message (with role="alert", set via textContent) rather than stacking new ones; four validators that each return true/false; a strength meter scoring 0–5 (length ≥ 8, upper, lower, digit, special) that sets the bar width to score/5 × 100% and the label; a touched Set, so blur validates and input re-validates only touched fields; changing the password re-checks a touched confirm field; submit calls preventDefault(), runs all validators, and either hides the form and shows #success-message or focuses the first .input-error. Test: an empty submit focuses Username; a weak password reads "Very weak"; a mismatched confirm error clears after the password is changed to match. Ask students where the server re-validates (in the real fetch("/api/register") endpoint). Reference: labs/module-5/l17-forms-validation/solution/.

L18 · Timers & Animation

Q1
In the browser, what does setTimeout return?
D) A numeric timer ID you can pass to clearTimeout()
Why: the callback hasn't run yet when setTimeout returns. What you get back is the timer's ID, which is the handle you use to cancel it.
Q2
What will console.log("A"); setTimeout(() => console.log("B"), 0); console.log("C"); output?
B) A, C, B
Why: even with a 0 ms delay, the callback waits in the task queue until the running code (the call stack) finishes, so "C" logs before "B."
Q3
What's the difference between setInterval and recursive setTimeout?
C) setInterval fires every N ms regardless of how long the work takes; recursive setTimeout waits for completion first
Why: slow async work inside an interval can overlap. A recursive timeout schedules the next run only after the current one finishes, which guarantees a gap.
Q4
Why use requestAnimationFrame instead of setInterval for visual animations?
A) It syncs with the display's refresh rate for smooth frames and pauses in background tabs
Why: rAF runs right before each repaint (60/120/144 fps) and stops when the tab is hidden, which saves CPU and battery. setInterval has no idea when the screen redraws.
Q5
What is debouncing?
D) Delaying a function until events stop firing, resetting the timer on each new event
Why: each new event resets the timer, so the function runs once after a pause. Option A describes throttling.
Q6
In what order do setTimeout(…"timer"…, 0), Promise.resolve().then(…"promise"…), console.log("sync") log?
B) sync, promise, timer
Why: synchronous code runs first, then the browser empties the microtask queue (promise callbacks) before it takes the next task (the timer). The order they were scheduled in doesn't decide the order they run in.

Look for: state variables declared outside the functions; updateDisplay formatting MM:SS with padStart(2, "0") and setting strokeDashoffset = CIRCUMFERENCE × (1 − remaining/total), where CIRCUMFERENCE = 2π × 130 ≈ 816.81; start() guarded by if (isRunning) return so a double-click doesn't create two intervals; the interval cleared and the done message shown at 0; pause/reset clearing the interval; presets for 25/15/5/1 min that pause, reset, and move the selected class; bonus ring colors of red under 30 s and green at 0. Stretch: an endTime set with Date.now() and remaining time recalculated each tick; prefers-reduced-motion turns off the ring transition. L19 · Local Storage

Q1
What does localStorage.getItem("key") return if the key doesn't exist?
B) null
Why: a missing key gives null, not undefined or "", and it never throws. That's why loaders use stored ? JSON.parse(stored) : fallback.
Q2
What happens when you store a JavaScript object directly with setItem?
D) It's stored as the string "[object Object]"
Why: storage only holds strings, so the object is converted with .toString() and the data is lost. Use JSON.stringify first.
Q3
What is the correct way to store an array in Local Storage?
A) localStorage.setItem("data", JSON.stringify(myArray))
Why: JSON keeps the structure and types (nested objects, numbers, booleans). JSON.parse turns it back into an array. Passing the array directly gives a flat "1,2,3".
Q4
How does sessionStorage differ from localStorage?
C) sessionStorage data is cleared when the tab is closed; localStorage persists until deleted
Why: same API and a similar ~5 MB limit. The difference is lifetime and scope: session data belongs to one tab, while local data is shared across tabs of the same origin.
Q5
Why should you never store passwords or auth tokens in Local Storage?
C) Any JavaScript on the page can read it, making it vulnerable to XSS attacks
Why: an injected script can read every key. Auth tokens belong in HttpOnly cookies, which JavaScript can't read.
Q6
Your to-do app is open in two tabs. In Tab A you add a task (setItem("todos", …)). Where does the storage event fire?
B) In Tab B (and any other open tabs of the same origin), but not in Tab A
Why: the tab that made the change already knows about it. The event goes to the other tabs, which is what makes cross-tab sync possible.
Exercise solution — Persistent To-Do List

Look for all 7 TODOs: 1 loadTodos with try/catch returning [] for missing or corrupted data, and saveTodos using JSON.stringify; 2 render clears the list, shows an empty state, and builds each li.todo-item (checkbox, span.todo-text via textContent, button.delete-btn "×", a done class, data-id); 3 addTodo trims and ignores blanks, then pushes { id: Date.now(), text, done: false }; 4 toggle with map and delete with filter, each followed by save + render; 5 a pluralized "X items left" count; 6 click + Enter to add, one delegated listener on #todo-list using closest(".todo-item") and Number(li.dataset.id), and "Clear completed"; 7 an initial render(). Test: add, tick, refresh, and the data is still there. Credit for polish: aria-labels on the checkbox and × button (the lesson's version has none) and a label for the input. The reference includes them. Reference: labs/module-5/l19-local-storage/solution/.

L20 · Working with APIs & Fetch

Q1
What does fetch() return?
B) A Promise that resolves to a Response object
Why: the data isn't there yet. The Response comes first, and response.json() is a second Promise that gives you the data.
Q2
What happens when fetch() gets a 404 response?
A) The Promise resolves normally with response.ok set to false
Why: fetch only rejects for network failures. HTTP errors are still valid responses, so check response.ok or response.status yourself.
Q3
What does the async keyword do to a function?
C) Makes the function always return a Promise and enables the use of await inside it
Why: async doesn't create a thread or speed anything up. It wraps the return value in a Promise and allows await inside the function.
Q4
Why use Promise.all() instead of multiple sequential await calls?
B) It runs requests in parallel, so the total time equals the slowest request rather than the sum of all
Why: sequential awaits start each request only after the previous one finishes. Promise.all starts them all at once.
Q5
What are the three UI states every fetch operation should handle?
D) Loading, data (success), and error
Why: these are what the user sees. Pending/resolved/rejected are the Promise's internal states.
Q6
Your page on http://127.0.0.1:5500 fetches from another site's API, and the console shows a CORS error. What's going on?
C) The API server didn't send a header allowing your origin, so the browser won't let your code read the response
Why: permission comes from the server's Access-Control-Allow-Origin header. fetch rejects with a TypeError, and the fix belongs on the server (or a proxy of your own), not in your fetch options.
Exercise solution — GitHub User Search

Look for: DOM references; showLoading (spinner + "Searching..."); showError that escapes the message; showUser built with createElement + textContent (avatar with alt text, name or "No name", @login, bio or "No bio available", repos/followers/following); async searchUser that trims and ignores blanks, uses encodeURIComponent, and branches 404 → "not found", 403/429 → rate-limit message, other !ok → the status, and catch → "Network error"; click + Enter listeners; bonus profile link (html_url, rel="noopener") and debounced auto-search. Classroom additions in the reference: a USE_MOCK switch (or ?mock) that serves mock-user.json when the room is rate-limited, AUTO_SEARCH off by default, and a latestSearch guard against stale responses. Reference: labs/module-5/l20-apis-fetch/solution/.
