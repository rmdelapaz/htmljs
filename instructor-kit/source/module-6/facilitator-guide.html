Module 6 — Capstone & Next Steps

The finale. Students build QuickNote, a complete note-taking app that uses every skill from the course, then learn to debug like a professional and plan what to build next. End the course with a working app on every screen and a clear next step in every workbook.

2 lessons ~2.3 hrs teaching Lessons L21–L22 Level Intermediate Maps to Day 5 PM (capstone)

How to Use This Guide

  • This is the capstone. L21 is one 90-minute guided build: you code each step live, the room mirrors you, and everyone passes a checkpoint before you move on. No step is "go build it yourself."
  • Live-code everything, and let it break. A missing comma or a typo'd ID in front of the class is a free debugging lesson. Read the red error out loud, find the line, fix it. That rehearses L22 before L22 starts.
  • Nobody falls off the train. Each step has a catch-up file in labs/module-6/l21-quicknote/checkpoints/. If a student is more than a step behind, hand them the checkpoint and let them rejoin at the next TODO. Finishing matters more than typing every line.
  • Blue blocks are concepts; teal blocks are hands-on; amber blocks are watch-outs.
  • Quiz answers here are for you. The student workbook has a 3-question subset of each lesson quiz, without answers, labelled with the lesson's question numbers; the separate Answer Key covers every question with matching numbers for grading.
  • L22 closes the whole course. Protect the last 15 minutes for the final Learning Journal entry and the course wrap-up. Don't let a stubborn bug eat the goodbye.
Pre-flight for the capstone

QuickNote fetches a quote from https://dummyjson.com/quotes/random. Open it in the classroom browser before class. If the network blocks it, that's fine: the app shows its fallback quote, and you get to teach graceful degradation with a real outage. Have Chrome or Edge with DevTools on every machine, Live Server working, and the starter plus the four checkpoint files ready to share (a USB stick or a shared folder). Test labs/module-6/l22-debugging/starter/ once through Live Server so you've seen all seven bugs yourself.

Before you start the module

Students need the Module 5 skills fresh: form validation (L17), timers and debounce (L18), localStorage (L19), and fetch with async/await (L20). Spend two minutes after lunch asking "what does JSON.stringify do? what does await wait for?" If anyone's setup is broken, pair them now. The capstone is no place for a first Live Server install.

Lesson Plans

L21

Building a Complete Project

90 min
Objectives
  • Plan an app before coding: feature list, data model, architecture
  • Separate a data layer (CRUD + localStorage) from rendering and event handling
  • Use one form for create and edit, with validation and a timed status message
  • Add debounced search, a category filter, a fetched quote with a fallback, event delegation and keyboard shortcuts
  • Keep user text safe with textContent
Teaching sequence
  1. Frame: show the finished app (5m). Open solution/quicknote.html. Add a note, edit it, search, filter, reload ("it's still there"), press N. Then say: "Every piece of this is something you already learned. Today we assemble it."
  2. Plan and architecture (7m). Walk the feature table (feature → skill → lesson), the note object (id from Date.now(), ISO timestamps), and the loop from the workbook diagram: user action → update state → save → re-render. Write the loop on the board and leave it up all afternoon.
  3. Step 1: tour the starter (3m). Everyone opens starter/quicknote.html with Live Server. Point out the hidden form, the empty #notes-grid, the role="status" span, and the DOM references already written at the top of the script.
  4. Step 2: data layer (10m). Live-code loadNotes/saveNotes with try/catch, then the CRUD functions and getNotes. Stress: no DOM in here. Checkpoint: createNote("Test","Hello","work") in the Console, then notes, then Application → Local Storage.
  5. Step 3: rendering (12m). formatDate, then renderNotes: clear, empty state, build cards in a DocumentFragment, append once, update the count. Uncomment renderNotes() in INIT. Checkpoint: reload and the Console-made note is a card. (Catch-up: step-3-render.html.)
  6. Step 4: form and validation (15m). showForm/hideForm, field errors placed right after their input, validateForm, showSaveStatus with clearTimeout, the submit handler. Land "one form, two modes": the hidden #note-id decides create vs update. Checkpoint: saving empty shows both messages; a valid save shows "Note saved!". (Catch-up: step-4-form.html.)
  7. Step 5: search and filter (7m). Type debounce from memory with the room (L18 callback). Wire input → debounced applyFilters, change → applyFilters. Point out the payoff: renderNotes already took the parameters. (Catch-up: step-5-search.html.)
  8. Step 6: the quote (6m). fetchQuote with res.ok check and a fallback in catch. Checkpoint: DevTools → Network → Offline, reload: fallback quote, app still works. (Catch-up: step-6-quote.html.)
  9. Step 7: polish (12m). One delegated click listener on #notes-grid for ✏️ and 🗑️ (including closing the form if you delete the note being edited), then the keyboard shortcuts. The transition CSS is already in the starter. Explain why the code uses N and not Ctrl+N.
  10. Test pass (5m). Students run the checklist in the lab README (or the workbook) against their own app and fix what fails.
  11. Quiz + journal (8m). Run Q1–Q5 as a poll (3m), then 5 minutes on the journal prompt.
Live-demo script — the three moments to rehearse
  1. The loop, visible. After Step 3, run this in the Console and narrate each line as a link in the chain: 
    createNote("Buy milk", "2 liters", "personal"); // update state + save
renderNotes();                                     // re-render
location.reload();                                 // load → still there
  2. The textContent test. Once the form works, save a note titled <img src=x onerror=alert(1)>. It shows as text. Then, in the Console, briefly swap one line to title.innerHTML = note.title, re-render, and let the alert fire. Undo it at once. Nobody forgets that demo.
  3. Delete while editing. Open a note in the form with ✏️, then delete that same note. Show why the delegation code calls hideForm() first: 
    if (noteIdInput.value === String(noteId)) hideForm();
    Without it, "Update Note" would try to update a note that no longer exists.
Lab — Build QuickNote (guided)

Everyone starts from labs/module-6/l21-quicknote/starter/quicknote.html (HTML + CSS done; TODOs 2a–7b in the script). Catch-up files for Steps 3–6 are in checkpoints/; the finished app is solution/quicknote.html (the lesson's complete source). The lab README has the step table, the test checklist, and the 8 stretch challenges as extensions.

Facilitator test checklist (walk the room with it): add ☐ · empty save shows both messages ☐ · edit ("Update Note") ☐ · delete with confirm and fade ☐ · delete the note being edited closes the form ☐ · search is debounced ☐ · category filter ☐ · reload keeps notes ☐ · quote loads and the offline fallback works ☐ · N / / / Esc work, and typing "n" in a field doesn't open a note ☐ · an HTML-looking title shows as plain text ☐ · clean Console ☐.

Early finishers: the extensions list (dark mode, export/import, drag & drop, Markdown preview, multi-tab sync, word count, confirmation modal, pin notes). Word count and pin notes fit in 10 minutes.

Watch-outs
  • Using a function before its step exists. ReferenceError: renderNotes is not defined usually means they uncommented INIT early. The starter keeps INIT commented for this reason.
  • IDs as strings. card.dataset.id and #note-id hold strings, but note ids are numbers. notes.find(n => n.id === "1713…") finds nothing. Hence Number(...) in the lesson code.
  • Field errors that pile up or jump. If clearFormErrors() isn't called at the start of validateForm(), each failed save adds another message. If the error span is searched in the whole parent, the title's message can land under the body.
  • Listeners inside renderNotes(). Some students attach click handlers to each card's buttons. They work until the next render. This is exactly why the lesson uses one delegated listener (quiz Q4).
  • "N typed into the title." Forgetting event.preventDefault() puts an "n" in the freshly focused title; forgetting the closest("input, textarea, select") guard opens a new note whenever someone types "n".
  • Ctrl+N. Students will ask. Chrome reserves it for a new window and never passes it to the page, so preventDefault() can't help. Single-key shortcuts outside fields are the Gmail and GitHub convention.
  • Stale data from earlier attempts. A half-built createNote can save malformed notes that break rendering later. Fix: Application → Local Storage → delete quicknote_notes, reload.
Check for understanding

Key answers: one form knows create vs edit because it checks whether the hidden note-id input has a value (Q1 · B); textContent so user text is shown as plain text, never run (Q2 · C); debounce(applyFilters, 300) = re-render only after typing pauses for 300ms (Q3 · A); one listener on #notes-grid because cards are rebuilt every render — event delegation (Q4 · D); quote API down = fallback quote, app keeps working (Q5 · B).

Journal (5m): students trace one feature (deleting a note, say) through user action → update state → save → re-render, naming the functions it calls, and note one feature they'd add and one part of the flow they're unsure about.

L22

Next Steps & Best Practices

45 min
Objectives
  • Read an error message for what, where and a likely why; use the debugging loop instead of random changes
  • Use console.table/group/time/assert, debugger and breakpoints
  • Organize code by concern, name things clearly, keep functions small, split files with modules
  • Recognize the common pitfalls: null queries, the async trap, ==, shallow copies, duplicate listeners, edge cases
  • Read modern syntax (?., ??, destructuring, spread/rest) and pick a next step: projects, Git, npm + Vite, a framework, TypeScript, testing
Teaching sequence
  1. Read the error (5m). Project Cannot read properties of null (reading 'textContent') and translate it together: WHAT (reading on null), WHERE (file:line, function), WHY (the selector matched nothing). Walk the five-row error table; stress "Unexpected token → check the line before."
  2. Console power tools + the debugger (7m). Live: console.table(notes) on QuickNote, a console.group, a console.time around a fetch. Then drop debugger; into deleteNote, reload with DevTools open, step over, hover variables. Finish with a Sources-panel breakpoint (no code change).
  3. The debugging mindset (3m). Use the workbook loop: read → reproduce → hypothesis → test → fix → verify. Mention rubber-duck debugging and mean it.
  4. Bug-hunt lab (15m). Launch labs/module-6/l22-debugging/. Students fill the worksheet row by row. At minute 12, debrief bugs 6 and 7 together if the room is stuck.
  5. Code organization + pitfalls (5m). Use QuickNote as the example: data / rendering / events sections, naming conventions, "if it's over 20–30 lines, split it," and the module file structure (type="module" needs a server). Tick off the pitfalls the lab already covered; spend your words on shallow copy vs structuredClone and == vs ===.
  6. Modern features, ecosystem, learning path (5m). One slide each: ?. and ?? (0 is kept), destructuring, spread/rest. Then the map: frameworks (React/Vue/Svelte), Vite + npm (npm create vite@latest, not the deprecated create-react-app), Node LTS, TypeScript, testing. Close on the suggested order and the 80/20 rule: build more than you watch.
  7. Quiz + final journal (5m). Q1–Q5 as a quick poll (2m); then the final journal prompt (3m in class, finish at home). Point students at the follow-on project menu in the workbook.
Live-demo script — the async trap in 30 seconds
let data;
fetch("https://dummyjson.com/quotes/random")
  .then(r => r.json()).then(d => { data = d; });
console.log(data);                   // undefined — fetch hasn't finished
setTimeout(() => console.log(data), 1000);  // now it's there

Run it in the Console, then rewrite it with await. This is Bug 7 in the lab, so it lands twice.

Lab — Bug Hunt: Snack Budget

Students open labs/module-6/l22-debugging/starter/ with Live Server and fix seven planted bugs in script.js, logging each in the worksheet (l22-debugging/README.md, also in the workbook). Five crash, in this order: missing comma (Unexpected token '{') → missing settings (reading 'weekly' of undefined) → selector typo (null) → formatprice is not defined → items.length is not a function. Two are silent: Bought works once, then never again (a listener added inside render()), and Load sample items uses samples before fetch finishes. Fixed version with // FIX n comments: l22-debugging/solution/.

Circulate for: students changing code before reading the message; fixing the reported line of the syntax error instead of the line before; "fixing" bug 6 by adding removeEventListener gymnastics instead of moving the listener out; wrapping bug 7 in a setTimeout "because it works now." That last one is a race, not a fix.

Watch-outs
  • Panic at red text. Model calm: read it aloud, click the file:line link. The message is a clue, not a verdict.
  • "The debugger does nothing." DevTools must be open before the reload; otherwise debugger is ignored (quiz Q5).
  • || vs ?? — score || 10 turns a real 0 into 10. Use ?? for defaults when 0, "" or false are valid.
  • Spread is shallow. { ...original } shares nested arrays; structuredClone makes a deep copy.
  • Ecosystem overwhelm. Some students leave thinking they must learn everything at once. Point at the suggested order: more vanilla projects first, then Git. Frameworks make more sense once they've built without one.
  • Outdated tutorials. Warn that create-react-app still appears in search results; it was deprecated in 2025. Start with Vite or a meta-framework.
Check for understanding

Key answers: Cannot read properties of null (reading 'textContent') = querySelector found nothing and returned null (Q1 · C); player.score ?? 10 with a score of 0 = 0 (Q2 · A); pushing onto copy.scores after a spread copy changes original.scores too — shared nested array (Q3 · B); a new React project today = Vite or a framework like Next.js (Q4 · C); debugger didn't pause because DevTools wasn't open (Q5 · B).

Final journal: which skill felt impossible at the start and makes sense now; one project from the Project Ideas table (or their own), the lessons it would use, and the very first step; one topic to revisit.

Closing the Course

Course wrap-up (15 min) 🎉

Showcase: two or three students demo their QuickNote on the projector, including one extension if anyone got that far. Recap the whole journey, one line per module: foundations → control flow & functions → data → the DOM → interactive pages → a complete app. Have everyone circle one project from the follow-on menu in the workbook and write its first step. Suggest they deploy QuickNote the way they deployed their HTML & CSS site, since a live link belongs in a portfolio. Hand out completion recognition. Remind them that every professional started exactly here: the difference is more time and more projects.
