L21 · Building a Complete Project

Q1
QuickNote uses one form for both creating and editing notes. How does the submit handler know which one to do?
B) It checks whether the hidden note-id input has a value
Why: The hidden note-id input is empty for a new note and holds the note's ID when editing, so one if/else picks createNote() or updateNote().
Q2
Why does renderNotes() put the note's title and body on the page with textContent instead of innerHTML?
C) So anything the user typed is shown as plain text and never run as HTML or script
Why: textContent always treats the text as plain text, so anything a user types — even something that looks like an HTML tag or script — is displayed, never run.
Q3
What does wrapping the search handler in debounce(applyFilters, 300) accomplish?
A) The notes re-render only after the user stops typing for 300ms, not on every keystroke
Why: Each keystroke restarts a 300ms timer, so the notes are only filtered and re-rendered once the user pauses typing.
Q4
Why does QuickNote attach ONE click listener to #notes-grid instead of a listener on every edit and delete button?
D) The cards are rebuilt on every render, so one listener on the parent (event delegation) handles every card, old or new
Why: This is event delegation. renderNotes() throws away and rebuilds every card, so listeners on individual buttons would be lost. One listener on the parent catches clicks from all current and future cards.
Q5
What happens in QuickNote if the quote API is down or the user is offline?
B) A fallback quote is shown and the rest of the app keeps working
Why: The try/catch in fetchQuote() catches the failure, shows a built-in fallback quote, and everything else keeps working. That's graceful degradation.
Exercise solution — Build QuickNote

Reference: labs/module-6/l21-quicknote/solution/quicknote.html, the lesson's complete source code, unchanged. Catch-up files after Steps 3–6: labs/module-6/l21-quicknote/checkpoints/. Look for:

  • Data layer with no DOM code: loadNotes in try/catch returning []; saveNotes after every change; createNote uses Date.now() ids, trims text, unshifts; getNotes matches category and lowercase search.
  • Rendering: clear → empty state → cards built in a DocumentFragment, appended once; title and body set with textContent; count reads "1 note" / "2 notes".
  • Form: hidden #note-id decides create vs update (Number() on the id); both error messages appear on an empty save, each right after its field; errors cleared before re-validating; status message restarts its 2-second timer with clearTimeout.
  • Search & filter: input → debounce(applyFilters, 300); change → applyFilters.
  • Quote: res.ok checked; the catch shows the fallback quote, so the app still works offline.
  • Polish: one delegated listener on #notes-grid; deleting the note open in the form calls hideForm(); N and / ignored while typing or with Ctrl/Cmd/Alt; Esc always closes.

Extensions (the 8 stretch challenges) are described with hints in labs/module-6/l21-quicknote/README.md; there is no single reference solution. Grade them against the same test checklist plus the new feature.

L22 · Next Steps & Best Practices

Q1
The console shows Cannot read properties of null (reading 'textContent'). What's the most likely cause?
C) querySelector didn't find the element, so it returned null
Why: querySelector returns null when nothing matches — usually a typo in the selector, or the script ran before the element existed. Reading .textContent on null throws this error.
Q2
A player's score is 0. What does const shown = player.score ?? 10; set shown to?
A) 0
Why: ?? only falls back when the left side is null or undefined. 0 is a real value, so it's kept. (With || you'd get 10, because 0 is falsy.)
Q3
You copy an object with const copy = { ...original }; and then push a new item onto copy.scores (an array). What happens to original.scores?
B) It changes too, because the nested array is shared
Why: Spread makes a SHALLOW copy: both objects share the same scores array. Use structuredClone(original) when you need a deep copy.
Q4
You want to start a new React project today. Which approach fits current best practice?
C) Use Vite (npm create vite@latest) or a framework like Next.js
Why: Vite (npm create vite@latest) or a framework like Next.js is the standard starting point now that Create React App is deprecated.
Q5
You add a debugger; line to your code and reload, but nothing pauses. What's the most likely reason?
B) DevTools wasn't open, so the browser ignored it
Why: The browser ignores debugger statements unless DevTools is open. Open DevTools (F12), then reload the page.
Exercise solution — Bug Hunt: Snack Budget

The lesson has no build exercise; this lab practices its error table and pitfalls. Fixed version: labs/module-6/l22-debugging/solution/ (each fix marked // FIX n in script.js). The bugs, in the order the Console reveals them:

#SymptomCause → fix
1SyntaxError: Unexpected token '{' — nothing runsMissing comma after the first object in seedItems, on the line before the one reported → add the comma.
2Cannot read properties of undefined (reading 'weekly')First visit: no saved settings, so settings.limits is undefined → settings.limits?.weekly ?? 20.
3Cannot read properties of null (reading 'replaceChildren')Selector typo "#item-lsit" → "#item-list".
4ReferenceError: formatprice is not definedCase-sensitive name → formatPrice.
5TypeError: items.length is not a functionlength is a property → items.length.
6No error: Bought works on the first click, then never againThe delegated listener is added inside render(), so each render stacks another copy and an even number of toggles cancels out → move listEl.addEventListener(...) out of render() so it runs once.
7Clicking Load sample items: Cannot read properties of undefined (reading 'forEach')Async trap: samples is used before fetch finishes → make the handler async, await fetch(...) and await response.json(), check response.ok, and catch errors.

Look for: a clean Console; Bought/Undo toggling every time with Spent/Left updating; three sample items added; deletes and reloads working. Accept any correct fix. For bug 2, settings.limits && settings.limits.weekly plus a default is fine; for bug 7, .then() with the dependent code moved inside it is fine. A setTimeout "fix" for bug 7 is not: it only hides the race. Follow-on projects (the workbook menu) are self-directed and have no key.
